## 1. Signatures, FE rewrites, folding

### FE signatures
All of these use `ExplicitlyCastableSignature`.
- **aes_encrypt / aes_decrypt** (`scalar/AesEncrypt.java:37-63`, `AesDecrypt.java:37-63`): 2 to 5 args. Every arg
  and the return type is `VARCHAR(65533)` or `STRING`. `CryptoFunction` is `AlwaysNullable, PropagateNullLiteral`
  (`scalar/CryptoFunction.java:33-34`), so **the result is always nullable**.
- **sm4_encrypt / sm4_decrypt** (`Sm4Encrypt.java:37-54`): the same, but only 2 to 4 args.
- **to_base64**: `STRING -> STRING`, `PropagateNullable` (`ToBase64.java:37-40`).
- **from_base64**: `VARCHAR|STRING ->` the same type, `AlwaysNullable` (`FromBase64.java:39-43`).
- **sm3**: unary, returns `VARCHAR` (`Sm3.java:39-44`).
- **sm3sum**: variadic, returns `VARCHAR` (`Sm3sum.java:39-51`). Both are `PropagateNullable`.

### Arg expansion
The FE always sends 4 or 5 args.
- `aes_x(s,k)` becomes `aes_x(s, k, '', MODE)` (`AesEncrypt.java:68-70`).
- `aes_x(s,k,iv)` becomes `aes_x(s, k, iv, MODE)` (`:72-74`).
- 4 and 5 args are passed through unchanged (`:76-82`).
- `sm4_*` works the same way (`Sm4Encrypt.java:59-72`).

`MODE` is a string literal holding the session variable `block_encryption_mode`:
- The variable defaults to `""` (`qe/SessionVariable.java:2019-2020`).
- Blank means `AES_128_ECB` for aes and `SM4_128_ECB` for sm4 (`CryptoFunction.java:81-90`).
- An invalid value raises `session variable block_encryption_mode is invalid with aes|sm4`
  (`AesCryptoFunction.java:82-89`, `Sm4CryptoFunction.java:48-55`).
- The mode is captured **when the function is built**, so `set block_encryption_mode` changes the literal in the plan.

The traffic confirms this, for example `aes_encrypt(varchar(4), varchar(32), text, text)` with the args `'text'`,
key, `''` and `'AES_128_ECB'`. The 3-arg BE registration (`enc.cpp:173-275`, IV = nullptr) is never used by Nereids.

### FE legality check
`AesCryptoFunction.checkLegalityAfterRewrite` (`AesCryptoFunction.java:97-107`) runs when arity ≥ 4 and arg 3 is a
string literal. It uppercases the literal and rejects modes outside the 27 AES modes with
`mode <UPPER> is not supported`. With 5 args and a non-GCM mode it raises `only GCM mode support AAD(the 5th arg)`.
Sm4 has no such check, so a bad literal sm4 mode reaches the BE and gives NULL.

### Folding
None of these functions has an FE executable (Java) implementation. `enable_fold_constant_by_be` defaults to
`false` (`SessionVariable.java:1774-1775`). FromBase64 is in any case excluded from BE folding
(`rules/expression/rules/FoldConstantRuleOnBE.java:244`). As a result:
- **All-literal calls reach the BE as `exec_plan_fragment`.** The three traffic files contain no
  `fold_constant_expr` RPC.
- `KEY name` (an encrypt key) is resolved by the FE to a string literal (`FoldConstantRuleOnFE.java:240`), with a
  case-insensitive name lookup. The BE sees `aes_encrypt(varchar(4), text, text, text)` with key `'aabbccdd1234'`.

### Modes in the recorded statements
- `AES_128_ECB` (also the default after `unset variable`)
- `AES_256_ECB`
- `AES_256_CBC`
- `aes_128_gcm` and `aes_256_gcm` (lower case, 5 args with AAD)
- `SM4_128_ECB`

## 2. BE algorithm (enc.cpp + eu.cpp; BE links OpenSSL 1.1.1s, `thirdparty/vars.sh:65`)

### Registration
`enc.cpp:469-503`.
- 4-arg `EncryptionAndDecryptMultiImpl`: the default mode (used for an empty mode string) is AES_128_ECB or
  SM4_128_ECB.
- 5-arg form: the default is **AES_128_GCM**.

### Return type and NULLs
- The BE return type is `Nullable(String)` (`enc.cpp:95-97`).
- Default NULL handling is in effect (`use_default_implementation_for_nulls` = true, `function.h:143`), so **any
  NULL arg gives NULL**.

### Per row
`enc.cpp:346-427`.
- **Mode** is looked up case-insensitively (`StringCaseUnorderedMap`, `enc.cpp:52-85`):
  - An unknown mode gives **NULL, not an error**. This includes an AES mode passed to sm4, or the reverse.
  - An empty mode means the registration default.
- **Key folding** (MySQL `my_aes_create_key`, `eu.cpp:125-145`):
  - `k = [0; bits/8]`, then `k[i % len] ^= key[i]` for every key byte.
  - bits is 128, 192 or 256, taken from the mode; SM4 is 128 (`eu.cpp:105-123`).
  - An empty key gives an all-zero key.
- **IV** (`eu.cpp:227-238`, `345-356`):
  - `ivlen = EVP_CIPHER_iv_length`: 0 for ECB, 16 for CBC/CFB*/OFB/CTR, 12 for GCM.
  - The buffer starts as `"DORISDORISDORIS_"`. `iv[..min(len,16)]` is copied over its front, and the first `ivlen`
    bytes are used.
  - So `''` gives `DORISDORISDORIS_`, `'0123456789'` gives `0123456789DORIS_`, and anything longer than 16 bytes is
    truncated.
  - ECB ignores the IV.
  - A null IV pointer with `ivlen > 0` gives NULL, but that only happens in the 3-arg form.
- **Non-GCM** (`eu.cpp:147-168`, `261-282`):
  - EVP runs with padding on (`enc.cpp:161`), so block modes use **PKCS#7**. Encrypting `n` bytes gives
    `n + 16 - n%16` bytes, so `''` gives one 16-byte block.
  - CFB, OFB and CTR are unpadded.
  - Any EVP failure (bad final block, bad padding, ciphertext length not a multiple of 16) gives **NULL**.
- **GCM** (`eu.cpp:170-216`, `284-332`):
  - Encrypt output is `IV(12) || ct || tag(16)`.
  - AAD is used only in the 5-arg form; the 4-arg form passes nullptr.
  - Decrypt **takes the IV from the first 12 input bytes and ignores the iv arg**.
  - Input shorter than 28 bytes, or a tag mismatch, gives NULL.
- A decrypt result can be the empty string, which is distinct from NULL.

## 3. sm3 / sm3sum
- Code: `function_string_digest.cpp:44-125`, registered at `:289`, with `sm3` an alias of `sm3sum` (`:295`).
- One SM3 (GB/T 32905) digest is computed over the **concatenation of all args**. Empty args are skipped (`:79`),
  which does not change the result.
- Output is 64 **lowercase** hex chars (`util/sm3.cpp:47-55`).
- Any NULL arg gives NULL.

## 4. to_base64 / from_base64
- Code: `fs.cpp:1134-1215`. Both use aklomp/base64 v0.5.2 (`thirdparty/vars.sh:540`, `url_coding.cpp:92-114`).
- **to_base64**:
  - `''` gives `''`.
  - Otherwise standard RFC 4648 (`A-Za-z0-9+/`), `=`-padded, with no line breaks.
- **from_base64**:
  - `''` gives `''`.
  - Invalid input gives **NULL** (`fs.cpp:1205-1206`), never an error.
  - Invalid input covers:
    - any byte outside the alphabet, including whitespace and newlines;
    - unpadded or truncated input (the final `state.bytes` must be 0);
    - data after the padding.
  - Non-zero trailing bits are accepted.
  - Rust equivalent: the `base64` crate with `GeneralPurposeConfig::new().with_decode_allow_trailing_bits(true)` and
    `DecodePaddingMode::RequireCanonical`. See the b5 doc §4.

## 6. Rust crates available offline
`~/.cargo/registry/src/*/` holds 239 crates. Of the crates relevant here, **only `base64-0.22.1` is present**, and it
is already in `Cargo.lock` (line 283) as a transitive dependency, not a direct one. These are absent: `aes`, `sm4`,
`sm3`, `cbc`, `ecb`, `cfb-mode`, `cfb8`, `ofb`, `ctr`, `aes-gcm`, `ghash`, `cipher`, `digest`, `openssl`.

Options:
- (a) Fetch the RustCrypto crates when the network is available.
- (b) Hand-port the needed pieces. Each is small, well-specified, and testable against the vectors above:
  - AES-128/192/256 (FIPS-197), with ECB and CBC plus PKCS#7;
  - GCM (GHASH, 12-byte IV);
  - SM4 (GB/T 32907) with ECB;
  - SM3 (GB/T 32905).

## 7. Risks
- **Untested modes.** The recorded suites exercise only ECB, CBC, GCM and SM4-ECB. CFB/CFB1/CFB8/OFB/CTR and SM4
  CBC/CFB128/OFB/CTR are untested by the oracle.
  - CFB1 has no RustCrypto crate.
  - OpenSSL's CTR uses a full 128-bit big-endian counter.
  - Getting these exactly right is low priority.
- **Empty iv in the vector path.** `iv_raw` for an empty slot or literal is a non-null pointer into the column chars,
  so `''` means the default IV, not NULL. Rust must treat an empty iv as "use the `DORIS…` default". Only a missing
  argument (the 3-arg form) would give NULL.
- **Output bytes.** The ciphertext is arbitrary binary data in a `VARCHAR`. The recorded rows always wrap it in
  `to_base64` or `hex`, so wire encoding of raw bytes is not exercised. Do not UTF-8-validate the result.
- **aklomp edge cases.** The aklomp decoder's behaviour on `XY=` (a single `=`) at end of input is not verified;
  treat it as NULL. No recorded statement hits it.
- **Load path.** The stream-load suite needs these functions evaluated in load column mappings (`streamLoadPut`
  plan), not only in query fragments.
