# Batch 3 research: string functions

C++ root: `.cache/doris-src/be/src`. Short paths: `fs.cpp` = `exprs/function/function_string.cpp`,
`pad.h` = `exprs/function/function_string_concat.h`, `misc.cpp` = `exprs/function/function_string_misc.cpp`,
`url/` = `exprs/function/url/`, `vsf.h` = `util/simd/vstring_function.h`.
Plan signatures come from the traffic corpus, dumped with the b2 tool
(`scratchpad/b2/ws/target/debug/examples/dump_fn_exprs` + `b2/condense_dates.py`); one file per suite in
`scratchpad/b3/sig/*.txt`. Notation: `T?` = node is_nullable; `lit` = STRING/INT_LITERAL arg.
The corpus file names carry the suite name twice (`<dir>.<suite>.<suite>.bin.gz`).

Default NULL handling (`use_default_implementation_for_nulls() == true`, function.h): any NULL argument gives NULL.
Only **nullif, char, parse_data_size** turn it off. Every constant-only call is evaluated at open (see b2 doc);
doris-rs already does this in `check_constants` (eval.rs:275-310), so a constant call that throws already fails in
exec_plan_fragment.

## Per function

### upper: `upper(varchar(50)) -> VARCHAR` (not nullable), slot arg
Used by set_operation_exprid_reuse (`upper(val)`, values 'a'..'d'). fs.cpp:563 (name), TransferImpl fs.cpp:567-627,
registered fs.cpp:1500 (alias `ucase` :1549). If **the whole column's bytes** are ASCII it does a bytewise ASCII
toupper. Otherwise every row goes through ICU `UnicodeString::fromUTF8(..).toUpper(Locale::getRoot())`
(fs.cpp:613-619). That is full Unicode case mapping (`ß`→`SS`), and invalid UTF-8 becomes U+FFFD. Rust
`String::from_utf8_lossy(b).to_uppercase()` matches it on the non-ASCII path. The suite only uses ASCII.

### replace: `replace(varchar(65533), varchar(1), varchar(2)) -> VARCHAR?`
hot_value_analyze_sync, nested twice:
`concat(replace(replace(CAST(int? AS VARCHAR), ':', '\:'), ';', '\;'), ' :', CAST(round(divide(double,double), 2) AS VARCHAR))`
(that is the FE's hot-value stats SQL). function_string_replace.h:57-159, registered as `FunctionReplace<ReplaceImpl, true>`
(fs.cpp:1540). An empty `old` returns the string unchanged (the `empty=true` branch, h:118-121; `replace_empty` is
the variant that inserts between characters). Otherwise a left-to-right, non-overlapping byte search, resuming after
the inserted text (h:146-153). That is the same as Rust `[u8]` replace. Return type String, with default NULLs.

### nullif: `nullif(int, int) -> INT?`
test_conditional_function: `nullif(1, slot INT?)` and `nullif(slot INT?, 1)`. Cases with a NULL or all-constant args
are FE-folded. nullif.cpp:52-128 computes `if(eq(a,b), NULL, a)` (:79-125). Since `eq` with a NULL gives NULL and
`if` treats NULL as false, **a NULL in either argument returns `a`** (NULL only when `a` is NULL). The return type
is `make_nullable(arg0)`. doris-rs can build this from the existing comparison `key`/`cmp` helpers (eval.rs ~560-580).

### find_in_set: `find_in_set(varchar(n) lit, varchar(30) slot?) -> INT?`
fs.cpp:307-343 (`FindInSetOp`), registered via `FunctionBinaryToType` fs.cpp:1447,1493.
- If `str` contains any `,` the result is 0.
- Otherwise it splits `strl` on `,` (empty parts kept) and returns the 1-based index of the first part equal to `str`
  (bytes, no trimming). No match gives 0.
- An empty list holds a single empty part, so `find_in_set('', '')` = 1.
- NULL gives NULL.

Corpus: `find_in_set("1", timea) > 0` in WHERE, and `find_in_set("1 ", timea)` projected. Expected
(test_find_in_set.out): `'1 '`→1, `'1,2,3'`→0 for "1 ", NULL→\N.

### char: `char(text 'utf8', int...) -> STRING?`, varargs, all literal
test_like_whole_string_match: `char('utf8', 10)`, `char('utf8', 13)` inside `concat(..)` in an INSERT … VALUES
(UNION node const exprs). misc.cpp:602-783.
- The charset arg (arg 0) is **ignored by the BE**. The FE accepts only a constant `'utf8'` (any case) and otherwise
  raises an AnalysisException (fe …/scalar/Char.java:57-65).
- Each INT becomes its big-endian bytes with leading zero bytes dropped (`integer_to_char_`, :751-770):
  `0` → one `\0` byte, `10` → `\n`, `0xE4B8AD` → 3 bytes. A NULL int arg is **skipped** (:628-630, :660-662).
- The bytes are concatenated. If the result is **invalid UTF-8 the row is NULL**, with no error (:739-745).
- There is no error text. Results only print through concat in this suite.

### url_encode / url_decode: `(text slot / nullable(text)) -> VARCHAR[?]`
function_string_url.cpp:213-275, util/url_coding.cpp:28-83. Default NULLs. Literal calls are FE-folded.
- **encode**: `[A-Za-z0-9.\-*_]` pass through, space → `+`, every other byte → `%XX` with **uppercase** hex
  (`to_hex` :28-30). `~` is encoded (`%7E`, confirmed in test_url_encode.out).
- **decode**: `+` → space. `%` needs `i+3 <= len`, otherwise it fails. The next 2 bytes are parsed with
  `istringstream >> std::hex >> int`, which **skips leading whitespace, accepts a sign, and stops at the first
  non-hex char**. Even so it always consumes 2 bytes (`i += 2`), so `%4G` → `\x04` and the `G` is dropped.
  A failed parse (`%GG`) is an error.
  - The value is truncated to a char, so `%-1` → 0xFF.
  - Unverified edge: libstdc++ `0x` prefix handling in `%0x`.
  - Failure: `Status::InternalError("Decode url failed")` → `(ip)[INTERNAL_ERROR]Decode url failed`.
    The suites never hit it; their data is all valid.

### parse_data_size: `parse_data_size(text slot?) -> LARGEINT?`, `parse_data_size(varchar(3) '1MB') -> LARGEINT`
fs.cpp:85-170, registered :1484. `use_default_implementation_for_nulls=false`, but a NULL row still gives NULL
(:121-124). The return type is nullable iff the arg is.
- Parsing (:138-168):
  - The leading run of `[0-9.]` (ASCII `isdigit` or `.`) is the number. An empty run is an error.
  - The run is passed to `std::stod`: `1.2.3MB` parses as 1.2 with unit `MB`, and a lone `.` throws.
  - The rest is the unit, looked up **case-sensitively**: `B kB MB GB TB PB EB ZB YB` = 2^0,10,…,80 (:74-79).
    `KB` and `mb` are errors.
  - The result is `(__int128)((long double)unit * value)`, truncated.
- Errors, exact text, ErrorCode INVALID_ARGUMENT:
  - `Invalid Input argument "{s}" of function parse_data_size`
  - `Invalid Input argument "{s}" of function parse_data_size, error: {e.what()}` when stod throws (libstdc++
    what() = `stod`)

  The corpus has `(127.0.0.1)[INVALID_ARGUMENT]Invalid Input argument "" of function parse_data_size` and the same
  with `"invalid"`. Each comes in the fetch_data response, in reportExecStatus (×2), and in cancel_plan_fragment.
  That is today's `ExecError::Coded{code: 33, name: "INVALID_ARGUMENT", msg}` runtime path, as in assert_true
  (eval.rs:764-777).

  Note that for `id IN (1,8)` row 1 is NULL and row 8 is `'invalid'`, and the error must still fire.
- Results: 1MB=1048576, 2.5MB=2621440, 0B=0.

### lpad / rpad: `(varchar(10)|text|char(10) [slot or lit], int lit, varchar lit) -> VARCHAR?` (always nullable)
pad.h:677-830 (`FunctionStringPad`), names fs.cpp:1334-1342. Return type `make_nullable(String)`, default NULLs.
Lengths are counted in **UTF-8 characters**, using the lead-byte length table (`iterate_utf8_with_limit_length`,
vsf.h:190-202), not bytes. Per row (pad.h:757-826):
- `len < 0` → **NULL**.
- If `str` has ≥ len chars → its **first len chars**, for **both** lpad and rpad (it truncates from the right, so
  `lpad('100000',2,'0')` = `10`). `len = 0` → `''`.
- Else, if the pad is empty → **`''`** (not str; MySQL compat). `rpad('123',5,'')` = `''`.
- Else: `need = len - str_chars`. Add `need / pad_chars` whole pads, then the first `need % pad_chars` chars of the
  pad. lpad puts the padding before str, rpad after.

Corpus:
- test_string_pad_function: lpad/rpad(varchar(10) slot, 2, '0') in `if(a=1, concat(..,':00'), NULL)`; literal
  cases `("",5,"")`, `("123",5,"")`, `("123",-1,"")` (expected `''`, `''`, `\N`); the NULL-arg cases are FE-folded;
  `rpad(char(10) slot, 10, 'x')` over 2048 rows → `asdxxxxxxx`.

  The CHAR value must arrive **without trailing padding** (`asd`, not `asd       `). Verify that the doris-rs CHAR
  read path strips padding, as C++ does.
- test_expr_zonemap_pruning: `lpad(CAST(number AS STRING), 5, '0')` in an INSERT … SELECT from `numbers()`.

### hex / unhex: `hex(text|varchar(20) slot?) -> VARCHAR?`, `unhex(varchar lit) -> VARCHAR` (not nullable)
- **hex(string)** (function_hex.cpp:54-112, registered :182) gives **uppercase** hex of every byte (`0123456789ABCDEF`,
  vsf.h:242-243); empty → `''`.
  - Other overloads: hex(BIGINT) (:114-160) is minimal uppercase with no leading zeros (`0` → `0`); hex(HLL) exists
    too. Neither is in these suites.
- **unhex** (fs.cpp:1006-1060, `string_hex_util.h` hex_decode): an odd length, `''`, or any non-hex digit gives
  **`''`**, not NULL and not an error. `unhex_null` is the nullable variant. Hex digits are case-insensitive.

Corpus (test_string_embedded_nul_zonemap): `unhex('610062'|'6100'|'0061')` in INSERT VALUES (32 rows each), and
`hex(s)` / `HEX(MIN(s))` / `MIN(HEX(s))`. Expected `610062`, `6100`, `0061`.

### starts_with: `starts_with(varchar(32|512)|char(10) slot?, varchar lit) -> BOOLEAN?`
fs.cpp:279-289 (`str.starts_with(prefix)`, bytes), class with expr-zonemap hooks fs.cpp:1361-1438, registered :1490.
Default NULLs. Only in WHERE, alone or under OR with IN_PRED / is_null_pred / is_not_null_pred.

### crc32: `crc32(varchar lit) -> BIGINT`
fs.cpp:211-229: zlib `crc32_z(0, bytes)` (IEEE CRC-32, unsigned 0..2^32-1), stored in Int64. Default NULLs.
`crc32(10)` arrives as `crc32("10")` (FE cast-folds). Expected: DORIS=348606243, APACHE DORIS=130583814,
"10"=2707236321. These equal Python `zlib.crc32`, and `crc32fast` (already a doris-exec dependency, route.rs:132)
gives the same.

### trim_in / ltrim_in / rtrim_in: `(varchar(n) [slot?|lit|substring(char lit)], varchar lit) -> VARCHAR[?]`, and 1-arg `ltrim_in(x)`/`rtrim_in(x)`
fs.cpp:724-1004. Registration fs.cpp:1508-1513 covers both the 1-arg (`Trim1Impl`) and 2-arg (`Trim2Impl`) forms.
Arg 1 is always constant (`get_arguments_that_are_always_constant() {1}`, :977). The return type is arg 0's type.
Default NULLs, so `trim_in(x, NULL)` is NULL and is FE-folded.
- **1 arg**: strip ASCII spaces `' '` only (:886-907).
- **2 args, remove of exactly 1 byte**: strip runs of that byte (`TrimUtil<…, true>`, vsf.h:107-170).
- **2 args, remove of 0 or ≥2 bytes** (the `_in` names, :920-925): the remove string is a **set of characters**
  and each end is stripped while the char is in the set.
  - If the remove set and the whole column are ASCII, a bitset of bytes is used (:780-829).
  - Otherwise the set holds UTF-8 characters (lead-byte length, :831-883). rtrim walks back over `10xxxxxx`
    continuation bytes.
  - An empty remove string strips nothing.
- Plain `trim/ltrim/rtrim` with ≥2 bytes strip the remove string as a *substring* repeatedly (`TrimUtil<…, false>`).
  This is a different function; keep it separate.

Corpus (test_trim_in): 66 call shapes, mostly literals under `check_fold_consistency`, plus slot calls with CJK sets
(`'省市杭州'`, `'杭余'`) over rows like `'浙江省杭州市'`. CHAR casts arrive as
`substring(char(n) STRING_LITERAL, 1, n)` (already supported).

### top_level_domain / first_significant_subdomain / cut_to_first_significant_subdomain: `(varchar lit | text slot[?]) -> STRING[?]`
url/function_url.cpp:48-66, url/domain.h:31-270 (ClickHouse port), wrapper url/functions_url.h:75-100
(`ExtractSubstringImpl`, default NULLs, never NULL for non-NULL input; "not found" = `''`).
- **get_url_host** (domain.h:45-129):
  - If the input starts with `//`, skip it.
  - Otherwise scan up to 16 bytes of the scheme: alnum and `.-+` continue, and a restricted char
    (` \t<>%{}|\^~[];=&`) gives an empty host. If `://` follows, skip it; else restart at byte 0.
  - Then scan the host. `.` records the last dot, `@` restarts the host, `:/?#` end it, and a restricted char
    anywhere gives empty.
  - Valid only if there is a dot, the host is non-empty, the dot is not last, and the char after the dot is not
    `:/?#`.
  - C++ reads `data[0]` and `data[1]` without a length check. Treat out-of-range bytes as 0.
- **top_level_domain** (:150-182): from the host, drop one trailing `.`. Return the text after the last dot; if
  there is no dot, or the text after it starts with a digit (IPv4), return `''`.
- **first_significant_subdomain** (:184-249):
  1. Take the domain with a leading `www.` stripped (only when the host is longer than 4), then drop one trailing
     `.`. Track the last 3 dots.
  2. 0 dots → the whole domain. 1 dot → the text before it.
  3. Otherwise take `host = text between the 2nd-to-last dot and the end` (or the first `/` after the last dot).
     If `tldLookup::is_valid(host)` (e.g. `com.cn`), return the label before it (between dots 3 and 2, or from the
     start). Else return the label between the last two dots.
- **cut_to_first_significant_subdomain** (:251-269): from the start of that label to the **end of the www-stripped
  domain** (a trailing dot kept). `www.google.com.cn` → `google.com.cn`.
- **The TLD table**: url/tldLookup.generated.cpp is a gperf perfect hash with 5045 entries (TOTAL_KEYWORDS :40),
  all two-level, e.g. `com.cn`, `co.uk`, plus IDN UTF-8 ones. Lengths are 4..34. The lookup is an exact,
  case-sensitive byte match (:126-139).

  Extract the `wordlist[]` strings (C octal escapes) into a static sorted `&[&[u8]]` or a `phf`/`HashSet`.
  `scratchpad` python one-liner: findall on `"…"` in the `wordlist[]` initializer, drop the empty ones → 5045.
  A generated .rs file of about 5045 lines will be needed (or `include_str!` of a list file).
- Expected (test_url_functions.out):

  | input | top_level_domain | first_significant_subdomain | cut_to_first_significant_subdomain |
  |---|---|---|---|
  | `www.baidu.com` | com | baidu | baidu.com |
  | `www.google.com.cn` | cn | google | google.com.cn |
  | `http://www.example.com/a/b/c?a=b` | com | example | example.com |
  | `https://news.clickhouse.com.tr/` | tr | clickhouse | clickhouse.com.tr (`com.tr` in table) |
  | `invalid url`, `''`, `' '`, `xxxxxxxx` | `''` | `''` | `''` |

## How results print
All string results are raw bytes in the MySQL text row. INT/BIGINT/LARGEINT print as decimal integers (Datum::Int is
i128; LARGEINT is already a supported type, value.rs:145). BOOLEAN results (starts_with) only appear in WHERE.
NULL prints as `\N`.

## doris-rs today
- None of the 20 functions exist (no hits in doris-exec/doris-be).
- Admission is in `check_nodes` (eval.rs:218-235): FUNCTION_CALL names are whitelisted; strings go through
  `string_call` (eval.rs:84-97, signature-checked, `text = CHAR|VARCHAR|STRING`).
- Evaluation is the big `N::FUNCTION_CALL => match function_name(n)` (eval.rs:670-840). Each arm gets
  `kids: Vec<(ColType, Vec<Datum>)>`, a per-arg `constant` flag (eval.rs:428-433), `rows`, and returns
  `(node_type(n)?, Vec<Datum>)`.
  - The family modules (`bits.rs`, `geo.rs`, `datetime.rs`) use the cleaner pattern: an `is_*_function(name)` +
    `supported(name, args, to)` in check_nodes (eval.rs:61-64, 238-240), and a single eval arm calling
    `module::eval(name, &types, &to, &args, rows)` (eval.rs:645-662).
  - Use the same pattern for a string family, e.g. an extended `strings.rs` or a new `url.rs` for the domain
    functions and TLD table.
- Reusable helpers: `strings.rs` `bytes()` (:273), `concat_column` (:320), `split_by_string` (:361) for the empty
  / UTF-8 splitting style, and the eval.rs comparison helpers for nullif. Errors go through `ExecError::Coded`,
  rendered `(ip)[NAME]msg` by doris-be `error_status` (query.rs:58-66). Use code 33 / `INVALID_ARGUMENT` for
  parse_data_size and code 6 / `INTERNAL_ERROR` (the default arm) for url_decode.
- `crc32fast` is available, so no new crate is needed. Nothing needed for ICU if Rust `to_uppercase` is used.

**test_expr_zonemap_pruning.** The suite sets `enable_profile=true, profile_level=2`. After each `COUNT(*)` it
greps the query profile for `ExprZoneMapFilteredSegments:` + `ExprZoneMapFilteredPages:` and asserts the sum is
**> 0**. One case asserts `ExprZoneMapFilteredPages > 0` alone: 8192 rows with `storage_page_size=4096`,
no compression, `starts_with(v,'m_')` must skip the `a_…` pages.

In the corpus these counters sit in the OLAP scan's `SegmentIterator` child profile
(exec/operator/olap_scan_operator.cpp:127,226) in 8 reportExecStatus calls, each about 80 KB of profile.

doris-rs sends **no runtime profile** in reportExecStatus (query.rs:575-620, `blank_report`) and has **no zonemap
pruning**. To pass honestly it needs:
- per-segment and per-page zonemap evaluation of the expr tree (C++ `evaluate_zonemap_filter`; for starts_with,
  `max < prefix` or `min ≥ next_prefix(prefix)` → no match, fs.cpp:1366-1438; plus IN / eq / OR / IS [NOT] NULL /
  int compare);
- reportExecStatus profiles the FE accepts.

Treat it as its own story, or drop the suite from this batch.

## What doris-rs needs
1. A string-function family module (bits/geo pattern) admitting the exact corpus signatures above: CHAR/VARCHAR/STRING
   args, an INT length for pads, varargs INT for char, and a constant arg 1 for the trim family.
2. Byte-exact ports: upper (ASCII fast path, Unicode `to_uppercase` otherwise), replace (empty `old` = no-op),
   nullif (`a` unless `a = b` is true), find_in_set (any comma in needle → 0), char (BE bytes, NULL args skipped,
   invalid UTF-8 → NULL), url_encode/url_decode (istringstream quirks; `Decode url failed` INTERNAL_ERROR),
   parse_data_size (case-sensitive units, the two error texts, LARGEINT), lpad/rpad (UTF-8 chars, truncation keeps
   the prefix, empty pad → `''`, len<0 → NULL), hex (uppercase) / unhex (bad input → `''`), starts_with, crc32
   (crc32fast → BIGINT), trim_in family (1-byte runs / char set / 1-arg spaces).
3. The ClickHouse domain functions plus the 5045-entry TLD table, generated from
   `be/src/exprs/function/url/tldLookup.generated.cpp`.
4. Verify CHAR slots read unpadded (`rpad(char(10))` → `asdxxxxxxx`).
5. Out of scope for a functions batch: the profile and zonemap work for test_expr_zonemap_pruning.
