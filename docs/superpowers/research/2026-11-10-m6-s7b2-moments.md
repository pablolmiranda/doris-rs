## Common facts (corpus)

- FE signatures: every one is `(DOUBLE[,DOUBLE]) -> DOUBLE`. Non-double args arrive wrapped in
  `CAST_EXPR:DOUBLE` (TINYINT/SMALLINT/INT/BIGINT/LARGEINT/FLOAT seen). `param_types` = DOUBLE(s).
- Every AGG_EXPR in the corpus has ret `DOUBLE?` (nullable) — scalar aggs are always-nullable; group-by
  cases have nullable args. Non-nullable args do occur (`kurt(val1)` with `SLOT_REF:DOUBLE#0`).
- Phases seen: one-phase (`finalize=true merge=false`, group by colocated key), two-phase
  (`finalize=false first_phase=true` → `finalize=true merge=true` on a `VARCHAR(65533)?` state slot),
  and the DISTINCT shape for kurt/skew (`finalize=false first_phase=false merge=false` over a
  dedup agg, then `finalize=true merge=true`). No ANALYTIC node uses any of them (aggdump checks
  analytic nodes too); window use exists only in non-group suites (`test_aggregate_window_functions`,
  `normalize_window_nullable_agg_test`).
- Two families of NULL handling:
  - **"ignore_nullable" (no wrapper)**: kurt, skew, regr_slope, regr_intercept. The function itself
    skips a NULL row (regr: skip if x OR y NULL); result column is always Nullable; NULL decided from
    the value (NaN → NULL / var<=0 → NULL). No flag byte in the serialized state.
  - **NullableAggregateFunction (variadic NULL wrapper)**: corr, corr_welford, covar, covar_samp,
    avg_weighted. A row with ANY NULL argument is skipped; if result_is_nullable and no row was
    accepted → NULL; otherwise the nested result, which may be a non-NULL 0.0 or NaN. Serialized:
    `bool flag` then nested state only if flag (only when result nullable).
- doris-rs partial states are its own encoding and never leave the BE (`aggregate.rs` header,
  [agg] A.3; stddev is tag 6: mean,m2,count LE). No C++ fragment is involved, so the C++ layouts
  below are informational — doris-rs just needs new tags with the same fields (bit-exact f64s).

## Formulas (bit-exact, in C++ evaluation order; all f64, `n as f64` conversions explicit)

### kurt / skew (`VarMoments<f64, L>`; skew L=3, kurt L=4; aliases kurt_pop, kurtosis / skew_pop, skewness)
State `m[0..=L]` all f64 (m[0] = count as f64).
- add(x): `m0 += 1; m1 += x; m2 += x*x; m3 += (x*x)*x; m4 += ((x*x)*x)*x` (left-to-right).
- merge: element-wise `+=` (no special case for empty).
- var = `if m0==0 {NaN} else max(0, (m2 - m1*m1/m0) / m0)` — `m1*m1/m0` = `(m1*m1)/m0`.
- moment3 = `if m0==0 {NaN} else if m0==1 {0} else (m3 - (3*m2 - 2*m1*m1/m0) * m1/m0) / m0`
  where `2*m1*m1/m0` = `((2*m1)*m1)/m0` and `(A)*m1/m0` = `((A)*m1)/m0`.
- moment4 = `(m4 - (4*m3 - (6*m2 - 3*m1*m1/m0)*m1/m0)*m1/m0)/m0` same associativity
  (`3*m1*m1/m0` = `((3*m1)*m1)/m0`; each `X*m1/m0` = `(X*m1)/m0`), 0 if m0==1, NaN if m0==0.
- skew result: if var NaN or m3 NaN or var <= 0 → NULL else `m3 / pow(var, 1.5)`.
- kurt result: if var NaN or m4 NaN or var <= 0 → NULL else `m4 / pow(var, 2) - 3`.
  (`pow(v,2)` == `v*v` exactly; `pow(v,1.5)` → Rust `f64::powf(1.5)` — libm pow, not `v*v.sqrt()`.)
- So: empty → NULL, one row → NULL (var 0), constant column → NULL.
- Verified in Python vs corpus: skew 1.4337199628825619 / 0.675885787569108 / distinct 1.1135657469022011;
  kurt 0.16212458373485106 / -1.4999999999999993 / distinct -0.7014368047529627. Data are small integers:
  all sums exact, so order-independent here.
- C++ serialized: raw `write_binary(*this)` = (L+1) f64 LE: skew 32 bytes, kurt 40 bytes; no flag.

### regr_slope(y, x) / regr_intercept(y, x)  (Youngs–Cramer)
Argument 0 is **y**, argument 1 is **x**. Skip row if either is NULL.
State: slope = `[sx, sy, sxx, sxy]`, n:u64; intercept = `[sx, sy, sxx, syy, sxy]`, n:u64.
- add(y, x): `sx += x; sy += y;` then `if n == 0 { n = 1; return }`;
  `n_old = n as f64; n_new = n_old + 1; scale = 1.0 / (n_new * n_old); n += 1;`
  `tx = x*n_new - sx; ty = y*n_new - sy;` (sx, sy already include x, y)
  `sxx += (tx*tx)*scale; syy += (ty*ty)*scale (intercept only); sxy += (tx*ty)*scale`.
- merge(rhs): if rhs.n==0 return; if n==0 {self = rhs; return};
  `n1 = n as f64; n2 = rhs.n as f64; nsum = n1+n2; dx = sx/n1 - rhs.sx/n2; dy = sy/n1 - rhs.sy/n2;`
  `n += rhs.n; sx += rhs.sx; sy += rhs.sy;`
  `sxx += rhs.sxx + ((n1*n2)*dx)*dx / nsum` (i.e. `rhs.sxx + (((n1*n2)*dx)*dx)/nsum`, then `sxx += that`);
  `syy += rhs.syy + (((n1*n2)*dy)*dy)/nsum`; `sxy += rhs.sxy + (((n1*n2)*dx)*dy)/nsum`.
  Note `a += b + c` is `a = a + (b + c)`.
- slope = `if n < 1 || sxx == 0.0 {NaN} else sxy / sxx`.
- intercept = same guard, else `(sy - (sx*sxy)/sxx) / (n as f64)` — `sx * sxy / sxx` = `(sx*sxy)/sxx`.
- Final: result NaN → NULL (so empty, constant x, or NaN from inputs → NULL). Inf is kept.
- C++ serialized: f64s in field order (sx, sy, sxx, [syy,] sxy) then n u64: 40 / 48 bytes; no flag.

### corr (sums)
State f64 m0,x1,y1,xy,x2,y2. add: `m0 += 1; x1 += x; y1 += y; xy += x*y; x2 += x*x; y2 += y*y`.
merge: element-wise `+=`. get: `if m0*x2 <= x1*x1 || m0*y2 <= y1*y1 {0.0}` (non-NULL 0 for a constant
column) `else (m0*xy - x1*y1) / sqrt((m0*x2 - x1*x1) * (m0*y2 - y1*y1))`.
Wrapper: no accepted row → NULL. One row → 0.0. Serialized C++: 6 f64 (48 B) after flag.

### corr_welford
State meanX, meanY, c2, m2X, m2Y: f64; count: i64.
- add: `count += 1; dX = x - meanX; dY = y - meanY; meanX += dX / (count as f64); meanY += dY / (count as f64);`
  `c2 += dX * (y - meanY); m2X += dX * (x - meanX); m2Y += dY * (y - meanY);` (uses the UPDATED means)
- merge: if rhs.count==0 return; if count==0 {self = rhs; return};
  `dX = rhs.meanX - meanX; dY = rhs.meanY - meanY; tot = count + rhs.count;`
  `meanX = (meanX*count + rhs.meanX*rhs.count) / tot` (all as f64), same for Y;
  `c2 += rhs.c2 + (((dX*dY)*count)*rhs.count)/tot`; `m2X += rhs.m2X + (((dX*dX)*count)*rhs.count)/tot`;
  `m2Y += rhs.m2Y + (((dY*dY)*count)*rhs.count)/tot`; `count = tot`.
- get: `if m2X == 0 || m2Y == 0 {0.0} else c2 / sqrt(m2X * m2Y)`.
- Serialized C++: meanX, meanY, c2, m2X, m2Y (f64), count (i64) = 48 B after flag.
- Corpus: group id=2 → 0.4539206495016017, which only comes out for add orders
  (30,22),(25,20),(36,21) or (25,20),(30,22),(36,21) — i.e. NOT insertion order; consistent with rows
  stored sorted by (id, k1). corr gives …019 in every order. doris-rs must scan rows in the same stored
  order (check its writer sorts by all key columns of the FE's schema for this auto-key DUP table).

### covar (alias covar_pop) / covar_samp
State sum_x, sum_y, sum_xy f64; count i64. add: `sum_x += x; sum_y += y; sum_xy += x*y; count += 1`.
merge: if rhs.count==0 return; element-wise `+=`.
- pop: `if count == 1 {0.0} else sum_xy/(count as f64) - (sum_x*sum_y)/((count as f64)*(count as f64))`
  (count 0 is NULL via the wrapper; would be NaN if a non-nullable empty state ever finalized).
- samp: `if count == 0 || count == 1 {0.0 (non-NULL!)} else sum_xy/((count-1) as f64) - (sum_x*sum_y)/((count as f64)*((count-1) as f64))`.
- Corpus: covar 0.666666666666667, covar_samp 1.0; group by id: ids 1–3 → 0.0, ids 4,5 (a NULL arg) → NULL.
- Serialized C++: sum_x, sum_y, sum_xy, count = 32 B after flag.

### avg_weighted(x, w)
State data_sum, weight_sum f64. add: `data_sum = data_sum + x*w; weight_sum = weight_sum + w`.
merge: `data_sum += rhs.data_sum; weight_sum += rhs.weight_sum`.
get: `if weight_sum == 0.0 {NaN (non-NULL, prints "NaN")} else data_sum / weight_sum`. No accepted row → NULL.
Caveat: both add and merge are compiled under `#pragma clang fp reassociate(on)` — like DOUBLE sum0 in
batch 1, clang may vectorize the per-block add loop into interleaved partial sums, so multi-row
non-exact data can differ from a sequential sum. Corpus inputs are exact (1 row; ints 1,2 with weights
1,-1 → 0/0 → NaN), so a sequential sum matches. Serialized C++: 2 f64 after flag.

## IMPORTANT: merge order / per-tablet partials (regr_slope, regr_intercept two-phase)

`support_type/regr_*`: table `d_table` 3 buckets, 3 rows (k1 = 1,2,3). The FE sends fragment 0 with
4 instances (`local_params` 4), instance 0 holding all three tablets' scan ranges, then a merge
fragment. Corpus: slope(float,double) = -2.792892135154929, slope(double,tinyint) = -0.5501239199999999,
intercept = 13.241664047161668 / 58.05515207633332.
Simulation over every split/order of the 3 rows (`sim/regr.py`): these bits come only from
partitions where rows are aggregated as per-tablet states then merged — by doris-rs's own
`route.rs` hash (crc32 % 3) k1=2 is bucket 0 and k1=1,3 share bucket 1; the states {k1=2},{k1=1,3}
merged in either order give the corpus values, while ONE state fed all rows in scan order
(k1=2, 1, 3) gives -2.792892135154927 and -0.5501239200000001 (wrong). doris-rs's scan
(`pipeline.rs:247`) concatenates all tablets of an instance into one block → one state → mismatch.
Fix options: in the first phase (`finalize=false`), keep one partial state per tablet (C++ scanner
granularity: one scanner per tablet feeds blocks into the parallel tasks) and emit them as separate
partial rows to be merged; or emit per-tablet partial blocks. Order of merging the two states did
not matter here. Integer-valued suites (kurt/skew, covar, avg_weighted) are order-free.

## non_nullable(x)
FE: `NonNullable` CustomSignature `ret(argType).args(argType)`, AlwaysNotNullable — any type, result
is the same type non-nullable. BE: if the column is Nullable and has any NULL →
`Status::InvalidArgument("There's NULL value in column {} which is illegal for non_nullable", data.name)`
(`data.name` = the argument column's block name; error code INVALID_ARGUMENT). Otherwise returns the
nested column (or the column itself if not nullable). `use_default_implementation_for_nulls=false`.
Not needed by any replayable suite: its only suites (test_and_or, test_regr_slope) are rejected;
none of their queries expect the error (they apply it to NULL-free columns / `where id >= 3`).
