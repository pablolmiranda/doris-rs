# Batch 3 research: math functions

C++ root: `.cache/doris-src/be/src/exprs/function/` (`math.cpp`, `round.h`/`round.cpp`, `modulo.cpp`,
`least_greast.cpp`, `function_width_bucket.cpp`, `function_math_unary_alway_nullable.h`,
`function_math_log.h`, `function_math_unary.h`).
Plan signatures were dumped from the traffic corpus with a scratch tool that walks every TExpr in a
fragment (output exprs, conjuncts, projections, intermediate projections, agg/sort/join/union/repeat):
`scratchpad/b3/fndump` (run as `fndump <suite.bin.gz> fn1,fn2|*`; dump in `scratchpad/b3/math/exprs.txt`).
C++ result rows came from the recorded `fetch_data` responses (`scratchpad/b3/math/rows.py`).
Notation: `T?` = node is_nullable; `D32(p,s)` = DECIMAL32 etc.

## Cross-cutting

- **Null handling.** Every function here uses the default IFunction NULL handling
  (`function.h:143`): a NULL argument row gives a NULL row, and the nested value is computed on
  a default value (no error, no NaN leak). On top of that, the always-nullable functions add their own NULLs.
- **Constants at open.** All-literal calls are evaluated at open. doris-rs already does this
  (`eval.rs:279-318` `check_constants`, which re-raises only `ExecError::Coded`). That covers
  `pmod(-9223372036854775808,-1)`, whose error the C++ BE returns on the **exec_plan_fragment
  response** (seen in test_mod's traffic).
- **Doubles print as shortest round-trip** (`row_text.rs:13-56`); `1/tan(0)` prints `Infinity`
  (seen in test_triangle; doris-rs's `special` already does this). All digits show, so **any 1-ulp libm difference is a mismatch** (see "libm" below).
- **DECIMAL→DOUBLE cast** in C++ is `(double)raw / (double)10^s` (`cast/cast_to_basic_number_common.h:338-345`).
  doris-rs casts through text, which rounds correctly. The two agree whenever both `raw` and `10^s` are exact in a double
  (raw < 2^53, s ≤ 22). That holds for every value in these suites.

## libm: the oracle matches correctly-rounded results; neither Rust's std on macOS nor the `libm` crate does

doris-rs runs on the macOS host. There, Rust's `f64::{tan,asin,acosh,atan2,ln,…}` call Apple's libm. The reference BE is
glibc (arm64 Linux). I compared every non-trivial double in the C++ rows of test_triangle,
test_math_unary_always_nullable, test_template_one_arg and test_template_two_args against three sources:
(a) Rust std on this host, (b) the `libm` 0.2.16 crate (musl/fdlibm port; already in Cargo.lock),
(c) a correctly-rounded (CR) reference (90-digit `Decimal`, then the C++ formula applied in doubles,
e.g. `1.0 / CR(tan(x))`). Scripts: `scratchpad/b3/libmchk` (Rust), `scratchpad/b3/math/cr.py`, `cr2.py`.

**Every oracle value equals the CR result.** The mismatches:

| case | oracle (= CR) | Rust std (macOS) | `libm` crate |
|---|---|---|---|
| cot(1) = 1/tan(1) | 0.6420926159343306 | …308 ✗ | ✓ |
| cot(10), cot(1e7) (and negatives) | 1.5423510453569202, -2.1573538153608958 | …198 ✗, …896 ✗ | ✓ |
| acosh(1.1) | 0.4435682543851154 | …153 ✗ | ✓ |
| asin(0.5) | 0.5235987755982989 | …988 ✗ | ✓ |
| ln(3) | 1.0986122886681098 | ✓ | …096 ✗ |
| atan2(1,0.1), atan2(123,-1), atan2(123,-0.1), atan2(±1,10), atan2(±0.1,10) | 1.4711276743037345, … | ✓ | ✗ (1 ulp) ×8 |

sec and csc (1/cos, 1/sin) matched under all three sources. acos, atanh and sqrt are only exercised
at trivial points (NULL, 0, π/2, or sqrt, which is IEEE-exact).
So no single library passes all four suites. Options for the planner:
1. **Run doris-rs on Linux/glibc** (for example in the oracle's docker network). std then calls the same glibc libm, so
   results match bit for bit. This is the most robust option.
2. **Per-function choice** that passes today's suites: `libm::tan`/`sin`/`cos`/`asin`/`acosh` (also `acos` and `atanh`,
   since musl's code is fdlibm, the same lineage glibc uses for acosh/atanh) and std `atan2`/`ln`/`powf`. This is fragile:
   it is only proven on the tested inputs.
3. **Correctly-rounded implementations** (for example a CORE-MATH port). The oracle behaves as CR on every input tested. glibc's
   exp/log/pow/sin/cos/tan/asin/atan2 claim < 1 ulp, not CR, so even this is not a guarantee.

## Per function (FE signatures from the corpus)

### floor — `floor(D128I(22,1)) -> D128I(22,0)` (test_grouping_with_alias)
round.h:818, registered round.cpp:28-66 (alias `dfloor`). `FunctionRounding<…, RoundingMode::Floor>`;
1-arg means scale 0. The return type is the FE's (`get_return_type_impl` returns arg 0; the result scale is read from
the block's result type, round.h:742-757). Decimal: `DecimalRoundingImpl::apply` (round.h:193-227) with
`scale_arg = in_scale − out_scale`; if > 0: `q = x / 10^scale_arg`, `rem = x − q·10^scale_arg`, Floor: `rem<0 → q−−`
(round.h:118-123); result `target>1 ? q·target : q`, `target = 10^(result_scale − out_scale)`. Corpus:
`floor(CAST(id AS D128I(22,1)) − 1.0)` with id=2 gives `1`. DOUBLE: `floor()`.

### truncate — test_function_truncate
Signatures: `truncate(DOUBLE) -> DOUBLE`; `truncate(DOUBLE, INT) -> DOUBLE?` with INT literal 0/1/−1 **or an INT slot**;
`truncate(D32(6,3) lit, INT −1) -> D32(6,0)`; `truncate(D32(9,{0,1,9}), 0) -> D32(9,0)`,
`truncate(D64(10,{0,9,10}), 0) -> D64(10,0)`, `truncate(D128I(19,{0,9,19}), 0) -> D128I(19,0)`;
with a column scale the result keeps the input type: `truncate(D64(18,9) lit, INT slot) -> D64(18,9)?`,
`truncate(D128I(19,s), INT slot) -> D128I(19,s)?`. Also FLOAT→DOUBLE casts, which are exact; doris-rs's text cast already round-trips them losslessly.
- Same machinery as floor, with Trunc (round.h:115-117). DOUBLE (round.h:251-320): scale>0: `trunc(x·10^d)/10^d`;
  <0: `trunc(x/10^-d)·10^-d`; `10^d` = `int_exp10` (size_t, saturates). This is exactly `round.rs::round_double` with trunc
  in place of round.
- **Column scale** (round.h:519-670): `apply_vec_vec`/`apply_const_vec` handle it row by row. DOUBLE uses the same per-row formula.
  DECIMAL uses `DecimalRoundingImpl::apply(x, in_scale, out, row_scale, result_scale)`. If `in_scale − row_scale ≤ 0` the raw value is
  **copied unchanged** (round.h:212-214). Example from the corpus: `truncate(123456789.123456789 (D64(18,9)), number=1)`
  → `123456789.100000000`; with −1 → `123456780.000000000`; `truncate(D128I(19,19) 0.1234567891234567891, 1)`
  → `0.1000000000000000000`.
- Errors: a const scale outside i16 gives `InvalidArgument("Scale argument for function truncate is out of bound: {d}")`
  (round.h:702-716; doris-rs already has this for round, `eval.rs:707-713`). For a column scale the text is
  `"Scale argument for function is out of bound: {d}"` (**no name**), with code OUT_OF_BOUND (`[E-218]`), round.h:527-533.
- Saturation (only at the edges, not in the corpus): `10^n` uses the native width (`exec_common/int_exp.h:69-120`: i32 >9 →
  INT_MAX, i64 >18 → max, i128 >38 → max). When the divisor saturates, Trunc/Round give 0, Floor gives `x<0 ? −target : 0`,
  and Ceil gives `x>0 ? target : 0` (round.h:157-180).

### pow (power/dpow/fpow) — `pow(DOUBLE, DOUBLE) -> DOUBLE[?]` (fix-overflow)
math.cpp:547-552, `FunctionMathBinary<PowImpl>` (math.cpp:574-730), aliases math.cpp:993-995. Not always-nullable:
the result is NULL only through argument NULLs; a negative base with a fractional exponent gives **NaN**. Special case
(math.cpp:649-667): with a constant exponent exactly 2.0, the leading rows with `|x| ≤ 2^26 && x integral` are `x*x`; from the first other row
on, every remaining row uses libm `pow`. In the corpus the exponent is FLOAT_LITERAL 0.2 (`1/5`, folded by the FE). In fix-overflow the
only non-NULL pow is `pow(1.0, 0.2) = 1`, which is exact, so there is no libm risk there.
fix-overflow is an INSERT…SELECT (agg, LEFT JOIN, decimal divide/ABS, `if`, CAST D128I(38,10)→DOUBLE,
CAST DOUBLE→D128I(20,2)/(38,6), `check_overflow_for_decimal=true`). The static check finds only pow missing. The
expected values are `NULL`, `0.00` and `NULL`, so none of the overflow error paths fire.

### pmod — `pmod(BIGINT, BIGINT) -> BIGINT?` (test_mod, both args literal)
modulo.cpp:506-556; the return type is always nullable (modulo.cpp:79-82). Integers: `b==0 → NULL`, else
`(a % b + b) % b` (modulo.cpp:538-548), so the result takes the divisor's sign. In C++ `a % b + b` can overflow (it wraps in practice: use
`wrapping_add`). `a == MIN && b == −1` throws INVALID_ARGUMENT
`"Division of minimal signed number by minus one is an undefined behavior, -9223372036854775808 % -1. "`
(modulo.cpp:42-53). doris-rs already produces this exact error for `mod` (`arith.rs:126-133`). In test_mod it reaches the FE in the
exec_plan_fragment response (`PStatus … [INVALID_ARGUMENT]…`), then the FE cancels. DOUBLE pmod:
`fmod(fmod(a,b)+b, b)`, b==0 → NULL. Only the BIGINT form is in the corpus; `mod` in the suite is already supported.

### least — `least(INT, INT, INT) -> INT? varargs` (test_partial_const_args_for_function)
least_greast.cpp:53-122, 355-366. The return type is arg 0's. The result starts as column 0, then for each next arg
`res = arg < res ? arg : res` (LessOp; strings by bytes). Constant args are broadcast. Corpus shapes:
`(slot, 5, 6)`, `(slot, 5, slot)`, `(slot, slot, slot)`, with slot `a INT?` over 0..9.

### bin — `bin(BIGINT) -> VARCHAR(65533)?` (test_keywords; arg `CAST(INT? AS BIGINT)`)
math.cpp:513-543: the binary digits of `(uint64_t)value` with no leading zeros; `0 → "0"`; a negative gives its
64-character two's complement. Corpus: 1 → `1`, 2 → `10`.

### width_bucket — test_width_bucket_function
Signatures: `(TINYINT×4) -> BIGINT` (union constants); `(DOUBLE, DOUBLE, DOUBLE, TINYINT) -> BIGINT[?]` with
expr `CAST(DATEV2 AS DOUBLE)`, `DOUBLE` slot or `CAST(BIGINT AS DOUBLE)`, min/max FLOAT_LITERALs (the FE folds
`date('2023-11-18')` to `20231118`), and n = 4.
function_width_bucket.cpp:63-122: `n = column3.get_int(0)` (row 0 only); `n ≤ 0` → InternalError
`"The desired number({n}) of buckets must be a positive integer value."`. Per row: `x < min → 0`;
`x ≥ max → n+1`; else if `(max−min)/n == 0` → 0 (**integer division for integer types**, so for TINYINT/…/BIGINT
a range smaller than n gives 0); else `(int64)(1 + (x−min) / ((max−min)/(1.0·n)))`. The result is not nullable except
through argument NULLs. Corpus constants: (1,2,3,2)→0, (6,2,6,4)→5, (3,2,6,4)→2, (29000,20000,60000,4)→2, (20221118,
20221117,20221119,2)→2.
**Hidden need:** C++ casts DATEV2→DOUBLE as `to_int64()` = `YYYYMMDD` (cast_to_basic_number_common.h:358-362).
doris-rs's CAST goes through text (`expr.rs:114-124`), so `"2022-11-18"` parses to **NULL**. Without a numeric
DATEV2/DATETIMEV2→number cast, the `width_bucket(v1, …)` queries print NULL instead of 0,1,2,3,4,5,5.

### cot / sec / csc — `(DOUBLE) -> DOUBLE?` (test_triangle; FE marks them nullable but the BE never adds NULLs)
math.cpp:389-411: `1.0/std::tan(x)`, `1.0/std::cos(x)`, `1.0/std::sin(x)` via `FunctionMathUnary`
(function_math_unary.h:34-83). There is no domain check: cot(0) = `Infinity`, cot(π) = `-8165619676597685`. libm risk on cot (see above).

### acos, acosh, asin, atanh, sqrt/dsqrt — always nullable `(DOUBLE) -> DOUBLE?`
math.cpp:53-74, 162-167, 366-372 (alias `dsqrt` math.cpp:986); `FunctionMathUnaryAlwayNullable`
(function_math_unary_alway_nullable.h:34-99). The value is `std::f(x)`; the row is **NULL** when `is_invalid_input(x)`, and
**NaN in gives NaN, never NULL** (h:85-93). Domains:
acos/asin invalid `x<−1 || x>1`; acosh `x<1`; atanh `x≤−1 || x≥1` (so ±1 gives NULL); sqrt `x<0` (−0.0 is valid and gives −0).
Corpus: literals `CAST(D32(2,1) 1.1/−1.1/−1.0/1.0 AS DOUBLE)`, `CAST(TINYINT −1 AS DOUBLE)`, wrapped in
`is_null_pred`; slots over {1.1, −1.1, 0, NULL…}; constants inside `numbers()` (DATA_GEN_SCAN iproj). test_template_one_arg:
`asin` over {1e-100, ±1e100, ±1, 0, 123, ±0.1, 1e-15} and `asin(CAST(nullable(D32(1,1) 0.5) AS DOUBLE))`.

### ln — always nullable `(DOUBLE) -> DOUBLE?`
function_math_log.h:28-89: `null = x ≤ 0` (so NaN gives NaN), value `std::log(x)`. The FE rewrites 1-arg `log(x)` to `ln`.
Corpus: `ln(slot)` over {1.1,…,5.6} and `ln(3)`.

### factorial — `factorial(BIGINT) -> BIGINT?` always nullable
math.cpp:413-480: `n<0 || n>20` → NULL, else `FACT_TABLE[n]` (20! = 2432902008176640000).

### atan2 — `atan2(DOUBLE, DOUBLE) -> DOUBLE[?]` (test_template_two_args; test_trim_in with VARCHAR→DOUBLE casts)
math.cpp:565-570 via `FunctionMathBinary` (not nullable; `std::atan2(y, x)`; NULL only through NULL arguments).
Shapes: slot/slot, slot/literal, literal/slot, all-literal in union (`nullable(1e100)`, `CAST(D64(10,10))`). libm risk
(see above). The template suites' other steps (CROSS JOIN, `truncate table`, `nullable()`) pass the static check;
only the function is missing.

## doris-rs today

- Dispatch (`eval.rs`): `check_nodes` (`eval.rs:197-275`) allows a FUNCTION_CALL by name. Family modules each expose
  `is_*_function` / `supported(name, args, to)` / `eval(name, types, to, args, rows)` (bits.rs:23-61, datetime.rs:501-540,
  geo.rs:14-82), wired in `eval_column` (`eval.rs:645-664`). `round` is special-cased: `round_call` (`eval.rs:120-137`)
  **requires a constant digits argument**, and `eval.rs:694-726` reads row 0 of digits only.
- `round.rs` has `round_double` and `round_decimal` (Round mode only, i128 throughout).
- `arith.rs` has `mod` (with the MIN % −1 error), `abs`, and DOUBLE/DECIMAL arithmetic.
- None of floor, truncate, pow, pmod, least, bin, width_bucket, cot/sec/csc, acos, acosh, asin, atanh, sqrt,
  ln, factorial or atan2 exists. `libm` 0.2.16 is in Cargo.lock as a transitive dependency only.

## What doris-rs needs

1. A `math.rs` family (`is_math_function`/`supported`/`eval`) wired like bits/datetime: cot/sec/csc, acos/acosh/asin/atanh,
   sqrt (+dsqrt), ln, factorial, atan2, pow (+power/dpow/fpow, with the `x*x` fast path for constant 2.0), bin, pmod
   (BIGINT; DOUBLE optional), least (+greatest is trivial), width_bucket (integer and double kinds, the `(max−min)/n==0` integer
   division, the n≤0 INTERNAL_ERROR).
2. Generalize `round.rs` to a rounding mode {Round, Trunc, Floor, Ceil}, used for `floor` and `truncate` (DOUBLE and
   DECIMAL32/64/128I). Allow a **non-constant INT scale** (per-row, the `in_scale ≤ row_scale` copy rule, and the
   OUT_OF_BOUND "Scale argument for function is out of bound: {d}" error). Keep the const-path InvalidArgument text with
   the function name.
3. pmod's MIN/−1 error is the same `Coded INVALID_ARGUMENT` as mod's; `check_constants` then fails the fragment at prepare.
4. A **numeric cast DATEV2/DATETIMEV2 → DOUBLE (and integers)** = `YYYYMMDD[hhmmss]`. Without it width_bucket's date queries print NULL.
5. **A libm decision** (see the table). With Rust std on macOS, test_triangle (cot), test_math_unary_always_nullable (acosh(1.1))
   and test_template_one_arg (asin(0.5)) will mismatch in the last digit. With the `libm` crate alone, test_math_unary_always_nullable (ln(3)) and
   test_template_two_args (atan2) mismatch. Best fix: run doris-rs on glibc. Otherwise choose per function, and add tests
   that pin the oracle values above.
