## 1. TTableFunctionNode and output rows

Thrift: `fnCallExprList: list<TExpr>`, `outputSlotIds: list<SlotId>`, `expand_conjuncts: list<TExpr>` (always `Some([])` here).
There is no `outer_slots` field. FE-side node fields used: `row_tuples = [child tuple..., fn tuple]`, `conjuncts`, `projections` + `output_tuple_id`.

- Layout (`prepare`): `_output_slots` = all slots of the node's row tuples in order = child tuple slots then fn tuple slots;
  `_child_slots` = slots of the child's row desc (the child's output tuple when it projects). fn i writes column `child_slots.len() + i`.
- `_slot_need_copy(i)`: child slot i is copied iff its id is in `outputSlotIds`; else it is filled with defaults
  (`insert_many_defaults`: NULL if nullable, 0/"" otherwise). Fn columns are always produced (fn slot ids are not checked;
  e.g. nested_lateral_view node 1 has outputSlotIds=[9], fn slot 10 absent, still produced). Since FE only drops slots nobody
  reads, doris-rs can copy every child slot — unobservable difference.
- Per child row: `process_row` on every fn. Inner fn with empty result (`_cur_size==0`) → child row skipped entirely
  (`_is_inner_and_empty`: any non-outer fn empty skips the row). Cross product with **fn[0] outermost, last fn fastest**:
  `get_value` is called on the last fn (emits a run), the others `get_same_many_values(len)` (repeat current value);
  when the last fn hits eos, `_roll_table_functions` forwards the nearest earlier non-eos fn and `reset()`s those after it.
- `_outer` (name suffix `_outer`, `set_outer`): an empty/NULL result emits exactly one row whose fn column is default
  (NULL, `insert_default` on a nullable column) and child slots copied. With several fns, an outer empty fn contributes NULL
  for its column while others iterate (its `get_same_many_values` inserts defaults). Not used by the 9 suites.
- Order: child rows in input order, each expanded in function order. Output block capped at `state->batch_size()` rows;
  a child row's expansion may span blocks (`_cur_offset` resumes). Child slot values copied with `insert_many_from(row, times)`.
- After building a block: `expand_conjuncts` filter, then node `conjuncts` filter, then (base operator) projections, then `reached_limit`.
- Fast path (`_can_use_block_fast_path`): one fn, `explode` over a single array → bulk copy; same rows/order as slow path.
- `expand_conjuncts` non-empty + outer fn (LEFT JOIN LATERAL unnest): child rows whose expansions are all filtered get one NULL row
  appended at end of the child block (order differs!). Not in these suites.
- eos = child eos and no pending child row.

## 2. Functions

explode_numbers(n) (`vexplode_numbers`): arg must be INT (FE casts). Output INT 0..n-1 ascending. n<=0 → 0 rows (`max(0,n)`),
NULL → `_cur_size` stays 0 → 0 rows (inner), one NULL row for `explode_numbers_outer`. Const arg with n <= batch_size precomputes;
larger n uses iota per call — same values. Output slot type INT; nullable iff FE marks it (literal arg: `INT` not null; nullable column arg: `INT null`).

explode(arr) (`VExplodeV2TableFunction`; `explode` maps to it, `explode_old` is the legacy one): elements in array order;
NULL array → 0 rows (outer: 1 NULL row); empty array → 0 rows (outer: 1 NULL row); NULL elements emitted as NULL rows.
Output column is always Nullable(element). explode(a, b, ...) zips into a STRUCT, length = max size, shorter padded with NULL
(posexplode adds an INT position field 0..). No suite uses multi-arg explode or posexplode.
explode_split(s, sep) is rewritten by Nereids to `explode(split_by_string(s, sep))` (seen in test_table_function_with_subquery).

## 3. ARRAY_LITERAL

TExprNode `node_type=ARRAY_LITERAL`, `type_ = [ARRAY(contains_null=true), SCALAR elem]`, `num_children` = element count, each child a
literal already of the element type (FE coerces: `[1,2,3]` → TINYINT children; `ARRAY(1,2)` same). C++ `VArrayLiteral::prepare`
builds a const column from each child `VLiteral`'s Field (children must be literals). In these suites ARRAY_LITERAL appears
**only as the explode argument** (agg_materialize, nested_lateral_view, lateral_view_with_inline_view); never selected.

Arrays reaching the result sink: **yes, only in test_split_by_string** (6 queries: replay files 0073, 0147, 0167, 0184, 0190, 0196),
from `split_by_string` in an OLAP-scan projection, type `ARRAY<VARCHAR>` (contains_null), slot nullable; carried through
SORT (ordered by k1/rid only) → DATA_STREAM_SINK → EXCHANGE → RESULT_SINK. Text form (`DataTypeArraySerDe::to_string`):
`[` + elements joined by `, ` + `]`; string elements wrapped in `"` with **no escaping** (`_nesting_level > 1`); NULL element
`null` (lowercase at nesting > 1); empty array `[]`; NULL array → MySQL NULL (0xFB). Ints inside would print bare.
Examples (replay 0078): `["a", "b", "c", "d", "e"]`, `[]`, `["", "", "", ""]`, `["你", "a", "好", "b", "世", "c", "界"]`, `\N`.
The 46 constant `select split_by_string(...)` / `split(...)` statements are folded by the FE and never reach the BE.

## 4. split_by_string(str, sep)

Return type `Array(Nullable(type of arg0))`; FE plans `ARRAY<VARCHAR>` for VARCHAR/CHAR/STRING args. Default NULL handling:
either arg NULL → NULL array. Elements never NULL. Per row:
- `str` empty → `[]` (empty array, not `[""]`), whatever `sep` is.
- `sep` empty → one element per UTF-8 character (ASCII fast path = per byte; else lengths from `UTF8_BYTE_LENGTH[lead byte]`).
- otherwise left-to-right non-overlapping search; every part kept, including leading/trailing/consecutive empties:
  `',,,'`/`','` → `["","","",""]`; `',,,,'`/`',,'` → `["","",""]`; `'a,b,c,'` → `["a","b","c",""]`;
  `'1,,2,3,,,,,,4,5,,abcde'`/`',,'` → `["1","2,3","","","4,5","abcde"]`. No match → `[str]`.
Const/column combinations all occur (sql_1 const-col, sql_2 col-const, sql_3 col-'', sql_4 ''-col, plus col-col).
In table_function_with_subquery it appears only inside explode; in test_split_by_string only as a projected value.

## 5. Minimal array representation for doris-rs

doris-rs is row-based (`Block { types: Vec<ColType>, rows: Vec<Vec<Datum>> }`), `Datum` is `doris_segment::writer::Datum`
(Null/Bool/Int/Float/Double/Bytes, shared with storage), `ColType::from_type_desc` returns None for nested types,
`DescTable::from_thrift` rejects nested slots ("slot 6 () of a nested type"), `check_nodes` rejects nested expr types.
Exchanges are in-process (`Chunk`), so no wire encoding of arrays is needed.

- Table-function side needs no array Datum: evaluate the fn argument specially inside the TF node — ARRAY_LITERAL → its children's
  datums; `split_by_string(x, sep)` → Vec of Bytes; any other array-typed argument → Unsupported. Elements get the fn slot type.
- test_split_by_string needs array values in Block rows only to be carried (projection → sort payload → exchange) and rendered.
  Two options:
  a. `Datum::Array(Vec<Datum>)` + `ColType` that can describe `ARRAY<scalar>` (e.g. ptype ARRAY + element ColType). Correct and
     extensible, but every exhaustive `match` on Datum (exec ~35 sites, segment writer/key_coder/sort) must handle/refuse it.
  b. Narrowest: `ColType { ptype: ARRAY, elem }` with the value pre-rendered as `Datum::Bytes("[\"a\", \"b\"]")` at evaluation,
     NULL array as `Datum::Null`. Byte-identical for these 6 queries; wrong the moment an array is compared, hashed, stored or fed
     to explode/array functions — so guard: allow ARRAY slots only where nothing but sort payload / exchange / result output reads them.
  Recommendation: (a) with refusals elsewhere if array_* functions are on the roadmap (other blocked suites use ARRAY_LITERAL with
  array_join/array_with_constant/element_at/percentile_array/map_agg); otherwise (b) is the minimal change.
- Also needed either way: DescTable accepting `ARRAY<scalar>` slots, `check_plan`'s slot-type check and `check_nodes` type check
  admitting them, `typed()`/`coerce` passing them through, `cell_text` rendering.
