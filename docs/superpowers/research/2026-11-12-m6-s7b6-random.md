## 1. random / rand in the C++ BE

**Signatures.** The FE has three signatures: `random()` → DOUBLE, `random(BIGINT seed)` → DOUBLE,
`random(BIGINT a, BIGINT b)` → BIGINT. There is **no 3-argument `random(seed, a, b)`**: the FE's
`withChildren` throws "random function only accept 0-2 arguments". The BE's `get_return_type_impl` gives
Int64 for 2 arguments and Float64 otherwise. Every argument must be a literal. The FE checks this in
`checkLegalityBeforeTypeCoercion` and raises "The param of rand function must be literal " (with the
trailing space). The BE repeats the check in `open()`.
`Random` is a `UniqueFunction` (volatile), so the FE never folds it. All 7 random queries of
`query_p0…test_query_sys` and all 4 of the nereids suite reach the BE as `exec_plan_fragment`.

**Generator.** The generator is `std::mt19937_64`, created in `open()` for each FunctionContext scope and seeded only
for `THREAD_LOCAL`. That is one generator per expression per fragment instance (pipeline task). It
is not reset between blocks, so the rows an instance evaluates take consecutive draws.
- 0 args: seeded with `std::random_device()()`, so it is nondeterministic.
- 1 arg (seed): `seed = (uint32_t)int64_value`, which truncates. A NULL seed gives seed 0, but the
  default null handling makes the result NULL anyway. Then `generator->seed(seed)`, the standard
  mt19937_64 init with that 64-bit value. **This is deterministic and matchable.**
- 2 args: seeded with `random_device`, so it is nondeterministic. Both arguments must be constant.

**Values.**
- Float: `std::uniform_real_distribution<double>(0.0, 1.0)`. For a 64-bit engine this is one draw:
  `(double)g() / 2^64` (u64→f64 rounds to nearest; a result ≥ 1 would become `nextafter(1, 0)`).
  libstdc++ and libc++ agree. Verified:
  seed 100 → 0.96166443084535547, 0.32358402105146866, 0.9732198251013584, 0.12884283299491089;
  seed 20 → 0.71565793752551599, … The first draw of seed 100 is `17739577640593830518 / 2^64`.
  These match the recorded replies exactly: `rand(20)`/`random(20)` = `0.715657937525516`, and
  `random(100)` = `0.9616644308453555`, `0.32358402105146866`.
- Int range: `std::uniform_int_distribution<int64_t>(min, max)` is **inclusive of max**, although the
  error says "[a, b)". The recording has `random(-5,-3)` = `-3`. Because the 2-arg form is always
  unseeded, its exact algorithm never needs to match. Any value in `[min, max]` is enough.
- Check: `min >= max` makes `execute` (not prepare) return `InvalidArgument`. The recorded client message is
  `errCode = 2, detailMessage = (<be-host>)[INVALID_ARGUMENT]random's lower bound should less than upper bound, but got [10, 1)`
  (query_p0 exchange 23, **not masked**: it must be byte-exact). Note that `min == max` is an error too.

**Wire formatting.** DOUBLE is col_type 5, decimals 31, length 22, as shortest round-trip text. doris-rs's
`row_text.rs` already prints this way (repr of 0.71565793752551599 is `0.715657937525516`). BIGINT is
col_type 8, length 20.

**Rust implementation.** Implement mt19937_64 directly (about 40 lines; no new crate needed) and
`f = (g.next_u64() as f64) / 18446744073709551616.0`, clamped below 1.0. Keep one generator per
(expr node, fragment instance), created at prepare and seeded with `seed as u32 as u64` or
OS-random. Draw rows in the order the instance evaluates them.

## 2. sleep(n)

- FE signature: `sleep(INT) → BOOLEAN`, `PropagateNullable`. `FoldConstantRuleOnBE` explicitly
  never folds `Sleep`. `sleep(null)` is folded by the FE to NULL and never reaches the BE (query_p0
  has only one sleep fragment). `sleep('1.1')` reaches the BE as `sleep(INT literal 1)`, because the FE
  folded the cast.
- BE: the result is `UInt8` 0 for every row (nullable when the argument is: NULL rows stay NULL
  and do not sleep). For each non-null row it calls `std::this_thread::sleep_for(seconds(n))` at execute time,
  not in open. The wire type is col_type 1 (TINY), length 1, and the text is `0`.
- doris-rs can simply sleep (`std::thread::sleep`, or an async sleep if evaluation is async) and
  return 0. No gate measures duration. Sleeping keeps the run's timing faithful (2 s + 1 s in the
  nereids suite, 2 s in query_p0), and skipping it gives no gain worth the divergence. Negative n:
  `sleep_for` with a negative duration returns at once, so treat it as 0.

## 3. The suites

How grading works: the strict gate (`grade.py`) compares only suites that pass the out gate *and* are
`"stable"` in marks.json. Marks are derived automatically (`marks.py`): a result column that differed
between reference runs becomes `masked_columns`, and the masked cells are replaced by `*` on both
sides before the comparison, NULL included. This **is** the mechanism for excluding a
nondeterministic exchange, and it already covers every unseeded random. An unseeded `random()` row
therefore does **not** fail the strict gate, as long as the column count, row count, column metadata and
the other columns match. Seeded random columns were identical across runs, so they are unmasked and
must be byte-exact. Marks are never written by hand.

### test_physical_translator: the ordering requirement

The table has 10 hash buckets on `a` (tablets …131, …133, …, …149). The FE sends **4 instances**
(`parallel_instance` 4): {131,139,147}, {133,141,149}, {135,143}, {137,145}. With zlib crc32 over the int's 4
LE bytes, `a=1` goes to bucket 1 (tablet …133) and `a=200` to bucket 5 (…141). Both are in the
**same instance**, which is why they got the 1st and 2nd draws of seed 100, not two first
draws. To be byte-exact, doris-rs must:
1. give each instance its own seed-100 generator (not one per query, nor per block reset);
2. scan that instance's tablets in scan-range order (133 before 141) and evaluate the projection
   on rows in emission order, sending row `1` before row `200` on the wire. Exchange 21 has no
   `unordered` mark, so the row order is compared.
Exchange 24 (`a + 2` with limit/filter) and the FE-only explains are already in scope. The plan check
(`scratchpad/b5/chk` logic, run against the current tree) reports only `random` as missing for this suite.

assertion only needs the two counts to be equal.

## Recommendation for batch 6

1. **test_physical_translator** (out and strict): seeded random as above, with a per-instance generator
   and draws in scan order. It is the cleanest win, and it is the one place the exact PRNG matters for the
   out gate as well.
2. **query_p0 test_query_sys** (out and strict): random (all four forms), the exact
   `[INVALID_ARGUMENT]random's lower bound…[10, 1)` error raised at execute, and `sleep` → TINY 0. Unseeded
   values are masked. The seeded `rand(20)` = first draw of seed 20 must be exact.
3. **nereids_p0 test_query_sys** (out only, since it is unstable): random and sleep, and nothing else at the
   BE level. Strict can never count it until the marks are re-derived.
4. **fold_constant_numeric_arithmatic**: random is trivially satisfied there, because column 4425 is masked. On the current tree, though, the
   plan check still refuses about 29 math functions (abs, asinh, atan, cbrt, conv, cos, …, gcd, lcm,
   signbit, even: the batch 5 math scope). So random alone will not pass it. Count it only once the math
   batch has landed.
