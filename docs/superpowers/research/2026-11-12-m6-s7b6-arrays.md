## 1. Nested values in a MySQL text row

Text result rows go through `serde->write_column_to_mysql_text` → `to_string` (serde dialect DORIS). Top level is
nesting level 1; ARRAY/MAP/STRUCT give their children level+1. Nullable keeps the level of its nested type.

- ARRAY: `[` + elements joined by `, ` + `]`; empty `[]`.
- MAP: `{` + entries joined by `, ` + `}`; an entry is `key` `:` `value` (no space after `:`); empty `{}`.
- STRUCT: `{` + fields joined by `, ` + `}`; a field is `"` name `":` value — the **name always in double quotes**, the
  names come from the **type descriptor** (`TTypeNode.struct_fields[i].name`), never from runtime args. `struct(...)`
  fields are named `col1..colN` by the FE; `named_struct` uses the given names.
- At level > 1: CHAR/VARCHAR/STRING wrapped in `"` with **no escaping**; DATE/DATETIME/DATEV2/DATETIMEV2/TIME/IPv4/IPv6/
  TIMESTAMPTZ also wrapped in `"` (number_serde/datetimev2_serde `_nesting_level > 1`). Integers, floats, doubles,
  decimals, booleans bare, same digits as top level (decimal with the type's scale: `1.0`, `0.5`, `12345.24`;
  DATETIMEV2 with the type's scale: `"2024-01-01 00:00:00.000000"`).
- NULL inside (element, key, value, field) at level > 1: `null` (lowercase). A NULL top-level cell: MySQL NULL `0xFB`.
- NULL_TYPE fields (`struct(null,..)`) are Nullable(Nothing), always `null`.
- Nested arrays recurse: `[[], []]`, map value arrays: `{"key":["ab", "efg", null]}`.
- **Gap in doris-rs** `row_text::cell_text`: quotes only string elements; date/datetime elements must be quoted too
  (array_range_second_unit output), and it cannot see nested element types (ColType is flat, §4).

Recorded bytes (length-encoded cell, hex):

  NULL → `fb`; empty string (array_join of `[]`) → `00`.
- `1\t[1, 2, 3]...` row: `0131 095b312c20322c20335d 095b...` ; row 2 `0132 fb fb fb`.

## 2. Function semantics

Notation: "default NULL handling" = any NULL argument → NULL result row (function not evaluated).

**array_with_constant(num BIGINT, v T) → ARRAY<Nullable T>, result NOT nullable** (own NULL handling).
- Per row: `n = value under num` (a NULL num row reads the nested value under the NULL — 0 for a scanned/cast NULL →
  `[]`, never a NULL result; doris-rs: treat NULL num as 0). If `n < 0 || n > 1000000` → error
  `INVALID_ARGUMENT` `Array size should in range(0, 1000000) in function: array_with_constant` (1000000 itself is allowed;
  checked for every row before any output). Otherwise `n` copies of v; NULL v → `n` NULL elements (`[null, null, null]`).
- v may be an array: `array_with_constant(number, [])` → ARRAY<ARRAY<NULL_TYPE>> elements `[]` (`[[], [], []]`).
- Both errors in the suite are constant (UNION const exprs) and fail at **exec_plan_fragment**: reply
  `PStatus{status_code: 33, error_msgs: ["(127.0.0.1)[INVALID_ARGUMENT]Array size should in range(0, 1000000) in function: array_with_constant"]}`
  then FE cancels; no fetch_data. doris-rs's `eval::check_constants` path already does this for coded errors.
  Args: `(-231 BIGINT, -138 SMALLINT)` (FE truncated -231.37104) and `(1000001 BIGINT, 1 TINYINT)`.

**array_join(arr ARRAY<string>, sep [, null_replace]) → STRING** (default NULL handling; nullable iff an arg is).
Non-NULL elements joined by sep; NULL elements skipped (when null_replace absent or empty; non-empty null_replace is
emitted in their place, with separators). Empty array or all-NULL → `""`. No leading/trailing separator.
`[Null,'hello',Null,'world',Null,'xyz','def',Null]`/`;` → `hello;world;xyz;def`. FE casts non-string arrays first:
`array_join([1,23,456], ';')` arrives as an ARRAY_LITERAL of VARCHAR; `array_join(array_range(n), ',')` arrives as
`CAST_EXPR ARRAY<VARCHAR(65533)>?(array_range(..))` — **CAST ARRAY<INT>→ARRAY<VARCHAR> is needed** (element-wise
int→string, offsets kept; NULL array stays NULL).

**array_range / sequence** (own NULL handling; result `Nullable(ARRAY<Nullable T>)`, elements never NULL).
- INT forms: `array_range(end)` = (0, end, 1); `(start, end)` step 1; `(start, end, step)`. Row is **NULL** if any arg
  NULL, `start < 0`, `end < 0` or `step <= 0` (no size check, so `(NULL, 5000000)` → NULL, not an error). Else
  `distance = end - start` (i64); `distance <= 0` → `[]`; else `start, start+step, ...` while `< end`;
  size `(distance-1)/step + 1`; size > 1000000 → error `INVALID_ARGUMENT` `Array size exceeds the limit 1000000`.
- DATETIMEV2 `array_range_second_unit(start, end, step INT)` (and minute/hour/day/week/month/quarter/year units; 2-arg
  datetime form = DAY): NULL if any arg NULL, `step <= 0`, or start/end not a valid date. Else emit `start`, add
  `step` units while `value < end` (packed u64 compare = chronological); end exclusive, microseconds carried; stop
  silently when the add overflows the date range; more than 1000000 elements → `Array size exceeds the limit 1000000`.
  Suite: `00:00:00.123456 → 00:00:03.123456` gives 3 elements; `00:00:00 → 00:00:02` gives 2.

**array_popback(a) / array_popfront(a) → type of a** (default NULL handling). popback drops the last element,
popfront the first; `[]`/one element → `[]`. Element NULLs kept.

**array_pushback(a, v) / array_pushfront(a, v) → Nullable(ARRAY<..>)** (own NULL handling): NULL array → NULL;
otherwise append/prepend v, a NULL v becomes a `null` element (`[null, 1]`, `[1, null]`). `[]`+1 → `[1]`. Result
element type is the FE's (`array_pushback(ARRAY<VARCHAR(1)>, VARCHAR(2)) → ARRAY<STRING>`; decimals share scale).

**map(k1, v1, ...) → MAP<Nullable K, Nullable V>, NOT nullable** (own NULL handling): per row the pairs in argument
order; NULL keys/values kept as entries; then `deduplicate_keys`: for a repeated key (NULLs equal each other) only the
**last** occurrence survives, at its own position. `CAST MAP→MAP` casts keys/values element-wise then dedups again.

**struct(v1..) / named_struct(n1, v1, ..) → STRUCT, NOT nullable**; fields = the value args (names ignored at
runtime); field nullability from the FE type (`contains_null`).

**element_at(STRUCT, const name|index)** → `Nullable(field)`: name match is case-insensitive; FE already rewrote the
int index `3` to the name `'f3'` (STRING). Unknown name → `Element not found for function element_at: name {} not
found in {}.`; bad int → `Index out of bound for function element_at: index {} should base from 1 and less than {}.`
(RuntimeError; not exercised).

**element_at(MAP, key)** → `Nullable(V)`: first entry (in stored order) whose key `compare_at == 0` (NULL key matches
a NULL probe); no match, NULL map or NULL value → NULL. Keys/probe of the same family (VARCHAR(32) key vs VARCHAR(2)
literal: byte compare; BIGINT; VARCHAR vs CJK text bytes).

**map_agg_v1(k, v) → MAP<Nullable K, Nullable V>, NOT nullable** (alias map_agg; "NotNullable" aggregate).
- add: a NULL key **skips the row**; otherwise if the key (raw bytes: string bytes, or the fixed-width value's bytes —
  float keys compare bitwise) is already present the row is **ignored (first wins)**; else append (k, v) — NULL v kept.
- Output order = first-seen order. No rows → `{}`.
- merge (two phase, `merge=true`, intermediate FE slot `VARCHAR(65533)` but the C++ state column is a MAP of the
  partial result): entries of each incoming partial added in its order, first wins again. Streaming pre-agg
  serializes each input row as a 1-entry map (`{}` for a NULL key). doris-rs's in-process exchange can encode the
  state any way (e.g. `Datum::Bytes` of the encoded pair list) as long as insertion order is kept.
- Duplicate keys across partials: the winner depends on arrival order — unobservable here (only element_at on keys
  unique per group is printed; test_dumplicate reads `m['b']`, unique in k2=2).

## 4. Minimal representation for doris-rs

- `Datum` (doris-segment `writer.rs`): add `Map(Vec<(Datum, Datum)>)` (ordered entries, duplicates allowed until
  dedup) and `Struct(Vec<Datum>)`; arrays already nest (`Array(Vec<Datum>)`). Every exhaustive match needs an arm:
  aggregate.rs (state encode/decode 279/326, as-number 418), pipeline.rs (hash 1119, `default_of` 1250 → `Map(vec![])`
  / Struct of field defaults, `truth` 1263), set_op/hash_join `row_key`, route.rs render (bucket hash; never a
  distribution key here), value.rs:170, row_text, key_coder (unreachable), stats_agg, strings, table_function.
- `ColType` is flat: ARRAY is encoded as `ptype=ARRAY, len=element ptype`, so it cannot express
  ARRAY<ARRAY<NULL_TYPE>>, MAP<VARCHAR(3), ARRAY<STRING>>, ARRAY<DATETIMEV2(6)> printing, or STRUCT field names. Needed:
  a recursive child description, e.g. `children: Vec<ColType>` (array: 1, map: key+value, struct: fields) plus
  `field_names: Vec<String>`, built from the whole `TTypeDesc` node list (pre-order; ARRAY 1 child, MAP 2,
  STRUCT `struct_fields.len()`; child nullability from `contains_null`/`contains_nulls`/`struct_fields[i].contains_null`).
  `from_type_desc` currently returns None for anything but ARRAY<scalar>; DescTable slot checks refuse nested slots.
- Flow: exchange is in-process (`exchange.rs` passes `Block`s of Datums), so no PBlock encoding is needed. Sort/
  group/join keys never involve MAP/STRUCT in these suites (sort keys are scalar slots; UNION passes slots through).
  The result sink needs a recursive `cell_text(datum, coltype, level)` per §1.
- Expressions to add: ARRAY_LITERAL of NULL_LITERAL children and zero children (NULL_TYPE element), nested
  ARRAY_LITERAL value args, CAST ARRAY→ARRAY and MAP→MAP, `map`, `struct`, `named_struct`, element_at on MAP/STRUCT,
  the array functions above, AGG_EXPR map_agg_v1 (both phases). `check_constants`' literal set lacks ARRAY_LITERAL;
  only matters if a constant array call can raise a coded error (none here).

## 5. Cannot match / risks

- array_with_constant with a NULL count reads C++'s value under the NULL; doris-rs has no such value. 0 is right for
  every NULL here (storage NULL, cast of NULL); a NULL produced by an expression with a non-zero hidden value would
  differ (not in any suite).
- map_agg_v1 merge winner for a key duplicated across partial states depends on C++ arrival order; not observable in
  these suites.
- map_agg_v1 / map() float keys compare by bytes (-0.0 ≠ 0.0, NaN = NaN bitwise); doris-rs must compare bits.
