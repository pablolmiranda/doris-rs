## As built (differences from the tasks below)

The tasks below are the plan as written. Implementation changed these:

- **Files:** the rounding and interval adds live in `datetime_round.rs`, the unix-time family,
  `months_between`, `next_day` and `date_format` in `unixtime.rs`, `convert_tz` in `tz.rs`,
  `money_format`/`format_round` in `numfmt.rs`, all dispatched from `datetime`/`strfn`.
- **Constant flags reach the date functions:** `datetime::eval` takes which arguments are
  constant. A constant period below 1 over a date column fails before any row naming the period
  alone; when every argument is constant C++ unwraps them, so the error names each one, the
  default origin too.
- **`new_version_unix_timestamp`** (TQueryOptions 167) rides in `RegexOptions` as
  `new_unix_timestamp`; `check_plan` runs under the query's clock, so all-literal unix-time
  calls fail at prepare as C++.
- **`str_to_date`** gains `%b`/`%M` and the twelve-hour `%h`/`%I`/`%l`/`%p`; an unported
  literal format is refused at check. `hex(BIGINT)` is new (the full run needed it).
- **Dates cast with any separator:** `CAST('1970/01/01 00:00:00' AS DATETIMEV2)` reads as C++
  does (any non-alphanumeric between year, month and day). The time part still takes `:` only.
- **Hashes:** Doris's `fmix64` constant (`0xc4ceb9fe1a85ec53`, not the published one) is copied;
  xxhash comes from `twox-hash` 2.1.
- **Refused on the write path:** `money_format` and `format_round` (a failing call there would
  only filter its row).
- **Fixes from the final review:** 1 Critical (non-ASCII format bytes), 4 Important and 5
  Minors, each test-first. The ledger lists them.
- **Supplements:** `test_expr_zonemap_pruning` (`be:profile_counters`), `pushdown_encode`
  (`be:sql_cache`: the reference's explain was served from the SQL cache) and
  `fold_constant_date_arithmatic` (`result:reference_date`: 12 selects return the day the FE
  folds `now()`).
- **The full runs.** `m6-s7b5-full-1`: 671 eligible, 3 failing (`str_to_date` twelve-hour
  formats, `hex(BIGINT)`, `pushdown_encode`). `m6-s7b5-full-2`: 670 eligible, 1 failing (the
  date separator). `m6-s7b5-full-3` on the final code (fresh FE, storage wiped): 669 eligible,
  0 failing in either gate; 727 suites pass the out gate (560 that reach the BE) and 606 the
  strict gate (526); the out ratchet gains 17, the strict ratchet 14. Its one difference outside
  the gate, `test_date_floor_ceil`'s all-constant error texts, was fixed test-first after it.
  The readback and swap checks pass.

## Calls (the designer's, for the user to check)

- **`convert_tz` uses chrono-tz** (tzdata 2025b; the reference has 2026e) and is refused past
  2099 in a zone with DST rules, where chrono-tz stops applying them and cctz does not.
- **`new_version_unix_timestamp`** (TQueryOptions 167) selects `from_unixtime_new` /
  `unix_timestamp_new`; the old versions are refused by name (no suite sends false).
- **Encoding** is evaluated wherever the FE puts it (projections, intermediate projections,
  union constants); grouping and sorting then run on the integer column as they do today.

## Global Constraints

- Byte-exact replies (spec §3). A feature that cannot match C++ is refused, naming it.
- Never `cargo fmt` whole packages. `rustfmt --edition 2021 --config max_width=150` only on new
  files or files clean at HEAD (check a copy on disk, not stdin); never on test files that
  declare `mod common`.
- `.cache/doris-src` is read-only. FE settings stay unchanged.

## Review Focus

1. **Out-of-range dates** from rounding, interval adds and `from_unixtime`: NULL or the C++ error,
   never a wrapped date.
2. **Scales**: DATETIMEV2(0..6) inputs keep their scale in `*_floor/ceil`, adds and `convert_tz`.
3. **UTF-8** in `locate`, `sub_replace`, `elt`: positions count characters, not bytes.
4. **Encoding round trip** for the longest and the empty string, and a too-long value's error.
5. **NULL rows** in every function, incl. a NULL period or format argument.
