# Golden Corpus and Rust Segment Reader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a committed corpus of tablets written by C++ Doris 4.1.5 with their exact rows, and a Rust crate that parses segment footers and decodes integer pages from it.

**Architecture:** Shell and Python under `oracle/corpus/` drive the running reference cluster: run SQL to create tables, capture expected rows with `mysql`, `docker cp` the tablet directories out, fetch tablet metadata over the BE HTTP API, and write a manifest. A Cargo workspace at the repo root gets its first crate, `crates/doris-segment`, which compiles the pinned proto files with `prost` and reads footers and pages; its tests iterate the manifest.

**Tech Stack:** bash, python3 (stdlib only), docker compose, mysql client inside the reference container; Rust 1.93, `prost` 0.13, `prost-build`, `protoc-bin-vendored`, `crc32c`, `lz4_flex`, `zstd`, `serde_json`, `sha2`.

**Spec:** `docs/superpowers/specs/2026-11-02-golden-corpus-design.md`

## Global Constraints

- Reference cluster is `oracle/compose/reference-single.yml`; container name `doris-oracle-doris-1`; BE storage root `/opt/apache-doris/be/storage`; FE on 9030 and 8030, BE HTTP on 8040, user `root`, no password.
- Protos copied verbatim from `.cache/doris-src/gensrc/proto/` at tag `4.1.5-release`; keep the Apache license header; record the source commit in a `README` next to them.
- Corpus v1 total size under 2 MB; expected rows always captured from the reference, never edited.
- Rust: edition 2021, `cargo fmt` clean, `cargo clippy -- -D warnings` clean, no `unsafe`.
- Commit after every task with the repo's commit style (imperative subject, body explains why).

## Review Focus

1. A `.dat` file shorter than 12 bytes or with a wrong magic: the reader must return an error naming the file, not panic. Test added to Task 4.
2. A footer whose crc32c does not match: error, not silent acceptance. Test in Task 4 flips one byte of a copied corpus file.
3. A compressed page whose decompressed size differs from `DataPageFooterPB`'s declared size: error. Test in Task 5 with a hand-corrupted page body.
4. A table with zero rows (empty rowset, `num_rows = 0`): footer parses, decode returns an empty column. Covered by the `empty_table` corpus table in Task 1 and asserted in Tasks 4 and 5.
5. Nullable columns where every value is NULL or none is NULL: the null bitmap edge cases. Covered by `all_null` and `no_null` rows in the `scalar_ints` table and asserted in Task 5.

### Task 1: Corpus tables and loader

**Files:**
- Create: `oracle/corpus/tables/01_scalar_ints.sql`, `oracle/corpus/tables/02_scalar_others.sql`, `oracle/corpus/tables/03_zstd_ints.sql`, `oracle/corpus/tables/04_empty_table.sql`
- Create: `oracle/corpus/bin/load.sh`
- Create: `oracle/corpus/README.md`
- Modify: `oracle/Makefile` (add `corpus-load`, `corpus-expect`, `corpus-extract`, `corpus` targets)

**Interfaces:**
- Produces: database `golden` on the reference with tables `scalar_ints`, `scalar_others`, `zstd_ints`, `empty_table`; `load.sh` is idempotent (`DROP DATABASE IF EXISTS golden` first).

- [ ] **Step 1: Write `01_scalar_ints.sql`**

DDL: `DUPLICATE KEY(k)`, `DISTRIBUTED BY HASH(k) BUCKETS 1`, `PROPERTIES("replication_num"="1")`. Columns: `k INT NOT NULL`, `c_bool BOOLEAN`, `c_tinyint TINYINT`, `c_smallint SMALLINT`, `c_int INT`, `c_bigint BIGINT`, `c_largeint LARGEINT`. Three INSERT statements (so three rowsets): first with 8 rows covering min, max, 0, -1, NULL in each column; second with 2000 rows generated by `INSERT INTO ... SELECT` from `numbers("number"="2000")` where `c_int = number % 7` (repeated values) and `c_bigint = number * 1000003`; third with 3 rows where every nullable column is NULL.

- [ ] **Step 2: Write `02_scalar_others.sql`**

Same table shape with: `c_float FLOAT`, `c_double DOUBLE`, `c_decimal DECIMAL(18,4)`, `c_date DATEV2`, `c_datetime DATETIMEV2(6)`, `c_char CHAR(8)`, `c_varchar VARCHAR(64)`, `c_string STRING`. Two INSERTs: 10 handwritten rows (empty string, 64-byte string, unicode, NULLs, 0.0 and -0.0, 1970-01-01 and 9999-12-31) and 500 generated rows with `c_varchar = concat('v', number % 5)` (dictionary path).

- [ ] **Step 3: Write `03_zstd_ints.sql`**

Same as `01` but `PROPERTIES("replication_num"="1","compression"="zstd")`, table `zstd_ints`, one INSERT of 1000 generated rows.

- [ ] **Step 4: Write `04_empty_table.sql`**

Table `empty_table (k INT, v VARCHAR(10))` with one `INSERT INTO empty_table SELECT 1, 'x' WHERE false` is not valid Doris; instead insert one row then `DELETE FROM empty_table WHERE k = 1` is a delete predicate, not empty. Use: create the table and run `INSERT INTO empty_table SELECT * FROM empty_table` (a no-op load that still publishes an empty rowset). The expected row count is 0.

- [ ] **Step 5: Write `oracle/corpus/bin/load.sh`**

Signature: `load.sh` (no args; reads `ORACLE` root from its own path). Runs, inside the container via `docker compose -f compose/reference-single.yml exec -T doris mysql -uroot -h127.0.0.1 -P9030`, first `DROP DATABASE IF EXISTS golden; CREATE DATABASE golden;` then each `tables/*.sql` in name order with `USE golden;` prepended. Fails on the first SQL error (`set -euo pipefail`, mysql exit code).

- [ ] **Step 6: Run it and verify row counts**

Run: `cd oracle && bin/../corpus/bin/load.sh && docker compose -f compose/reference-single.yml exec -T doris mysql -uroot -h127.0.0.1 -P9030 -N -e "SELECT 'scalar_ints', count(*) FROM golden.scalar_ints UNION ALL SELECT 'scalar_others', count(*) FROM golden.scalar_others UNION ALL SELECT 'zstd_ints', count(*) FROM golden.zstd_ints UNION ALL SELECT 'empty_table', count(*) FROM golden.empty_table"`
Expected: `2011`, `510`, `1000`, `0`.

- [ ] **Step 7: Add Makefile targets and README, commit**

Targets: `corpus-load` runs `corpus/bin/load.sh`; `corpus-expect`, `corpus-extract` are added in Tasks 2 and 3; `corpus` runs all three in order. README describes the layout and the "never edit expected files" rule.

fn every_corpus_segment_footer_parses_and_rows_sum_to_expected() {

### Task 5: Decode integer columns (BIT_SHUFFLE, LZ4F and ZSTD) against the corpus

**Files:**
- Create: `crates/doris-segment/src/page.rs` (page read and decompress), `crates/doris-segment/src/ordinal.rs` (ordinal index), `crates/doris-segment/src/bitshuffle.rs`, `crates/doris-segment/src/column.rs`
- Test: `crates/doris-segment/tests/ints_corpus.rs`

**Interfaces:**
- Consumes: `SegmentFile`, `pb::segment_v2::{ColumnMetaPb, PagePointerPb, PageFooterPb, DataPageFooterPb, OrdinalIndexPb, EncodingTypePb, CompressionTypePb}`.
- Produces:
  - `pub fn read_page(file: &SegmentFile, ptr: &PagePointerPb, codec: CompressionTypePb) -> Result<Page, Error>` where `pub struct Page { pub footer: PageFooterPb, pub body: Vec<u8> }`; body is decompressed when `footer.uncompressed_size != compressed length`, and `Error::PageSizeMismatch` when the decompressed length differs from `footer.uncompressed_size`.
  - `pub fn ordinal_index(file: &SegmentFile, meta: &ColumnMetaPb) -> Result<Vec<(u64, PagePointerPb)>, Error>` (first ordinal of each data page, in order).
  - `pub enum IntValues { I8(Vec<Option<i8>>), I16(..), I32(..), I64(..), I128(..), Bool(Vec<Option<bool>>) }` and `pub fn read_int_column(file: &SegmentFile, column_unique_id: i32) -> Result<IntValues, Error>`.
  - Null handling per `DataPageFooterPb`: `nullmap_size` bytes of RLE-encoded null bitmap at the end of the body when the column is nullable; decode with the same RLE scheme as `be/src/storage/segment/page/rle_page.h` (`run length encoded bits`, see `RleEncoder<bool>`).
