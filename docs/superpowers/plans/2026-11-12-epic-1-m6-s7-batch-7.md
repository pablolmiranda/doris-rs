# Epic 1 M6 Story 7, Batch 7: Arrays, Maps and Structs — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** doris-rs carries arrays, maps and structs through expressions, exchanges, unions and
the result sink. It runs the array functions, `map`/`struct`/`named_struct`, `element_at` on a
map or struct, and `map_agg_v1` as the C++ BE does. Eligible goes from 680 to up to 687, all
passing both gates.

**Architecture:**
- **Types:** `ColType` (`crates/doris-exec/src/value.rs`) gains a recursive child description,
  built from the whole `TTypeDesc` node list. `Datum` (`crates/doris-segment/src/writer.rs`)
  gains `Map` and `Struct`.
- **Printing:** the result sink prints a nested cell recursively (`row_text.rs`).
- **Functions:**
  - The array functions go in a new `crates/doris-exec/src/arrays.rs`.
  - `map`/`struct`/`named_struct`/`element_at` go in a new `crates/doris-exec/src/maps.rs`.
  - `map_agg_v1` goes in `aggregate.rs`.
- **Storage:** none. Nested values only live in memory, between expressions, exchanges, unions
  and the sink.

**Tech Stack:** Rust (`doris-exec`, `doris-segment`, `doris-be`, `doris-fixtures`), Python oracle.

**Spec:** `docs/superpowers/specs/2026-11-08-epic-1-m6-query-breadth-design.md` §2 (row 7), §3.

## Calls (the designer's, for the user to check)

- **Representation:** `ColType.children` (ARRAY: the element; MAP: key, then value; STRUCT: the
  fields) and `ColType.field_names` (STRUCT only).
  - The old flat ARRAY encoding (`len` = the element's ptype) stays readable through
    `element()`, so existing callers keep working.
  - `Datum::Map(Vec<(Datum, Datum)>)` keeps entries in order; `Datum::Struct(Vec<Datum>)`.
- **Nested values are refused** as sort, group, join and partition keys, in a scan or table
  sink, and in a hash. The refusal names the operator. The batch's suites need none of these.
- **`array_with_constant` with a NULL count** gives `[]`, reading the count as 0. C++ reads the
  value hidden under the NULL, which is 0 for every NULL these suites produce (research §5).
- **`map_agg_v1`'s partial state** crosses the in-process exchange as `Datum::Map` in insertion
  order, and the first key wins on merge. C++'s winner for a key repeated across partials
  depends on arrival order; no suite can observe it.
- **Map keys compare by bytes.** Floats compare by bit pattern, so -0.0 ≠ 0.0 and NaN = NaN.

## Global Constraints

- Byte-exact replies (spec §3). A feature that cannot match C++ is refused, naming it.
- Never `cargo fmt` whole packages. `rustfmt --edition 2021 --config max_width=150` only on new
  files or files clean at HEAD (check a copy on disk, not stdin); never on test files that
  declare `mod common`.
- `.cache/doris-src` is read-only. FE settings stay unchanged.

## Review Focus

1. **NULL at each level:**
   - a NULL top-level cell is MySQL NULL;
   - a NULL element, key, value or field prints `null`;
   - a NULL array argument to `array_pushback` gives NULL;
   - `array_join` skips NULL elements.
2. **Size limits:**
   - `array_with_constant(1000000, x)` runs, and 1000001 or -1 fails with C++'s text;
   - an `array_range` past 1000000 elements fails with "Array size exceeds the limit 1000000";
   - neither may panic or allocate unbounded memory first.
3. **Duplicate and NULL map keys:**
   - `map()` keeps the last duplicate, at that occurrence's position;
   - `map_agg_v1` keeps the first;
   - `map_agg_v1` skips a NULL key, and `map()` keeps it;
   - `element_at` matches a NULL key to a NULL probe.
4. **Text inside nested values:** quotes and commas inside a string element are printed as-is,
   without escaping. Dates and datetimes inside are quoted, and decimals keep the type's scale.
5. **A nested value reaching an operator that cannot take it** (sort key, group key, join key,
   hash partition, table sink) is refused at prepare, naming it, and never panics.
