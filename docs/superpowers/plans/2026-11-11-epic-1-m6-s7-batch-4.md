# Epic 1 M6 Story 7, Batch 4: Group Commit — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** doris-rs runs `GROUP_COMMIT_BLOCK_SINK` as the C++ BE does for the four suites it
alone blocks. Eligible goes 652 → 656, all passing both gates.

**Architecture:**
- **Plans** (`doris-exec/src/fragment.rs`): a type-12 sink is a write; its params are the
  `olap_table_sink`, its mode `group_commit_mode`. The FE's internal plan
  (`GROUP_COMMIT_SCAN_NODE` → `OLAP_TABLE_SINK`) plans as `WritePlan::GroupCommit`.
- **Sink split** (`doris-exec/src/sink.rs`): checking and routing rows (counts, error log) is
  separated from committing them, so the user's fragment checks its rows and the internal load
  commits them later under its own transaction.
- **Queues** (new `doris-be/src/group_commit.rs`, `GroupCommitMgr`): per table, open load
  queues; a load joins an open queue or starts one with `streamLoadPut`; one committer thread
  per queue commits when its interval passes or its bytes reach the limit, then calls
  `loadTxnCommit` (or `loadTxnRollback`) and wakes sync loads.
- **Load paths** (`doris-be/src/load.rs`): `exec_plan_fragment` for type 12 (async reports at
  once with the queue's label and txn; sync waits; `cancel_plan_fragment` ends a sync wait
  with CANCELLED); stream load with the `group_commit` header.

**Tech Stack:** Rust (`doris-exec`, `doris-be`, `doris-fixtures`, `doris-wire`), Python oracle.

**Spec:** `docs/superpowers/specs/2026-11-08-epic-1-m6-query-breadth-design.md` §2 (row 7:
features in batches, most suites unlocked first), §3. The C++ behaviour is in
`docs/superpowers/research/2026-11-10-m6-s7b3-group-commit.md`: every task reads it.

## As built (differences from the tasks below)

The tasks below are the plan as written. Implementation changed these:

- **Queued bytes count every column as nullable.** The recorded `receive_bytes` is 87 for three
  rows the reports count as 25 bytes each: the queue's block is made nullable.
- **Integer `add`/`subtract`/`multiply`/`mod` and `abs` run on the write path.** The large-data
  suite's generated column `c = abs(a + b)` reaches the BE as `CAST(abs(a + b) AS DOUBLE)` in
  the stream plan's destination expressions.
- **A load joins its queue under the lock the committer takes** (the final review's one
  Critical: a load could add rows to a queue already committed). A new queue takes its first rows
  before its committer starts.
- **Commit outcome as C++:** loads see only the write's status (a failed write is CANCELLED
  "cancel group_commit, label=…"); `loadTxnCommit` is retried up to 5 times on a transport error
  or DELETE_BITMAP_LOCK_ERROR; a commit the FE refuses still ends the queue OK.
- **Sync loads** are registered before the fragment is answered and woken by a cancel at once.
  A load with too many filtered rows still joins its queue (no rows) and names it, as C++.
- **Stream loads:** the header and the plan must agree on group commit; Content-Length is
  checked with C++'s texts.
- **Fixes from the final review:** 1 Critical, 3 Important (Review Focus tests, a queue listed
  without a committer, reformatted untouched code) and 7 Minors, each test-first where a test
  can show it. The ledger lists them.
- **The full runs.** `m6-s7b4-full-1` ran the binary from before the final review: 656 eligible,
  0 failing. `m6-s7b4-full-2` on the final code (fresh FE, storage wiped): 656 eligible, 0 failing
  in either gate; 709 suites pass the out gate (542 that reach the BE) and 591 the strict gate
  (511); each ratchet gains 5. The readback and swap checks pass.

## Calls (the designer's, for the user to check)

- **No WAL.** C++ writes async rows to a write-ahead log so a restart can replay them. doris-rs
  keeps queued rows in memory: a BE stopped before the commit loses them. No suite restarts a
  BE with an open queue.
- **The user fragment routes its rows; the internal load commits them as routed.** Both plans
  name the same table at the same moment, so their partitions agree. A row the internal plan's
  partitions do not hold fails the internal load (rollback), never silently moves.
- **`load:group_commit` stays unsupported.** It is a supplement need of
  `test_group_commit_stream_load_high_concurrency_async` (concurrent stream loads). This batch
  adds stream-load group commit for `large_data`, but that suite's concurrency is not claimed.
- **A queue's interval and byte limit are those of the put reply that created it**, as C++ does:
  an ALTER reaches only queues created after it (the interval suite depends on this).

## Global Constraints

- Byte-exact replies (spec §3): reports, put and commit requests equal the recorded ones except
  ids that are random per run (load ids, labels' hex, query ids, txn ids, tablet ids,
  backend ids, timestamps).
- Never `cargo fmt` whole packages. `rustfmt --edition 2021 --config max_width=150` only on new
  files or files clean at HEAD; never on test files that declare `mod common`.
- `.cache/doris-src` is read-only. FE settings stay unchanged.
- A feature that cannot match C++ is refused, naming it.

## Review Focus

1. **A sync load cancelled while its queue is committing**: the cancel must not hang and must
   report CANCELLED once; the commit still happens.
2. **Two loads racing for one table's queue**: both join the same queue or the second starts a
   new one; never two open queues for one table with the same schema version.
3. **A queue whose internal load fails** (put refused, tablet error): its sync loads report the
   failure; async loads already reported OK (as C++); the txn is rolled back.
4. **Shutdown with an open 300 s queue**: `wait_idle` and shutdown do not wait for it.
5. **A filtered row in a group-commit load**: counted, logged, never queued.

### Task 3: GroupCommitMgr

**Files:**
- Create: `crates/doris-be/src/group_commit.rs`; Modify: `crates/doris-be/src/lib.rs`
- Test: `crates/doris-be/tests/group_commit.rs`

**Interfaces:**
- Consumes: Task 2's `Checked`, `commit_checked`, `plan_write` for `GroupCommit`.
- Produces: `GroupCommitMgr::new(tablets, fe, master, error_dir)`;
  `mgr.join(table_id, schema_version, index_size, rows: Checked) -> Result<Arc<Queue>, String>`;
  `Queue::{label(), txn_id(), wait(deadline: Option<Instant>) -> Option<TStatus>}`.

Rules (research §"What the BE does"): a queue is reused when it is not `need_commit`, has the
same schema version and index count, and `now - start < interval`; else a new one:
`streamLoadPut` exactly as recorded (load_sql, label `group_commit_<hi:016x>_<lo:016x>` of a
fresh load id, token `group_commit`, user `admin`, `max_filter_ratio 1.0`, …). `need_commit`
when bytes ≥ data_bytes after a join, or the interval passed. The committer waits for
`need_commit` and no joining load in flight, then `commit_checked` under the put reply's txn,
then `loadTxnCommit` as recorded (`group_commit true`, `receive_bytes`, `auth_code 0`,
`thrift_rpc_timeout_ms 180000`, the heartbeat token, db/table ids, backend id), or
`loadTxnRollback` on an error; then the queue is closed and its waiters woken.
