# Epic 1 M6 Story 7, Batch 3: Math, Strings, Aggregates, Interval Calls — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** doris-rs runs 48 more query features as the C++ BE does, in four families. Eligible
goes 620 → 654, all passing both gates.

**Architecture:**
- **Interval calls:** `COMPUTE_FUNCTION_CALL` is evaluated as the FUNCTION_CALL it names, for
  the date add/sub family only (`eval.rs`).
- **Math** gets `math.rs` (bits/datetime pattern: `is_math_function`/`supported`/`eval`), with
  transcendental functions from the `core-math` crate (correctly rounded, as glibc is on every
  recorded value). `round.rs` gains a rounding mode for `floor` and `truncate`, and a column
  scale. A DATEV2/DATETIMEV2 → number cast is added.
- **Strings** get `strfn.rs` (same pattern), plus `url.rs` with the domain functions and a TLD
  table generated from `tldLookup.generated.cpp`.
- **Aggregates** are new `State` variants in `aggregate.rs` (or `moments.rs`' pattern in a new
  `stats_agg.rs`), with `ARRAY<DOUBLE>`/`ARRAY<BOOLEAN>` slots and `element_at`.

**Tech Stack:** Rust (`doris-exec`, `doris-be`, `doris-fixtures`, `doris-wire`), Python oracle.

**Spec:** `docs/superpowers/specs/2026-11-08-epic-1-m6-query-breadth-design.md` §2 (row 7:
features in batches, most suites unlocked first, until the user stops it), §3.

## Calls (the designer's, for the user to check)

- **The group-commit sink is batch 4, alone.** Research sizes it at 3–4 days (shared per-table
  queues, a BE-started `streamLoadPut` → internal plan → `loadTxnCommit`, timers), and no
  suite replays without harness work. Every family here is checkable by replay.
- **Transcendentals come from `core-math`.** The C++ results are glibc's, which equal the
  correctly rounded value on every recorded input. Rust std on macOS misses 5 of them
  (cot(1), acosh(1.1), asin(0.5), …) and the `libm` crate misses 9 (ln(3), atan2). `core-math`
  1.4 gave every recorded value (scratch check `b3/cmchk`). It builds C with `cc`.
- **Two suites leave the batch.** `test_expr_zonemap_pruning` asserts profile counters
  (`ExprZoneMapFilteredSegments`) doris-rs does not report; `subquery_unnesting` (any_value)
  first needs a CROSS_JOIN mark join. `any_value` and `starts_with` are not added.
- **linear_histogram's JSON numbers follow the recorded replies.** rapidjson is not in
  `.cache`; the expected texts are the corpus's (`0.0`, `-0.5`).
- **Stats-table partial updates stay refused.** They are FE background deletes no suite reads;
  `test_regr_slope` passed the batch 2 gate with one. The full run decides those four suites.

## Review Focus

1. `truncate(x, scale_col)` with a row scale larger than the input scale copies the value; a
   scale out of range is OUT_OF_BOUND "Scale argument for function is out of bound: {d}".
2. Always-nullable math outside its domain (`asin(2)`, `ln(0)`, `acosh(0.5)`, `factorial(21)`)
   is NULL, never NaN or an error.
3. `lpad`/`rpad` count UTF-8 characters, and a string longer than `len` keeps its first `len`
   characters (both functions); an empty pad gives `''`; a negative length gives NULL.
4. `percentile` over a group with one row or a level of 0/1 gives that row's value exactly;
   NULL rows are skipped and an empty group is NULL.
5. `exponential_moving_average` depends on row order: an unordered scan of several tablets
   would differ, so it runs only over the stored order (one tablet, or a refusal).

### Task 3: Math functions

**Files:** create `crates/doris-exec/src/math.rs`; modify `eval.rs` (dispatch, the date →
number cast), `crates/doris-exec/Cargo.toml` (`core-math = "1.4"`); tests in `tests/math.rs`.

Rules (math research, per-function sections):
- `cot`=1/tan, `sec`=1/cos, `csc`=1/sin, no NULLs added. `acos`/`asin` outside [-1,1],
  `acosh` < 1, `atanh` outside (-1,1), `sqrt`/`dsqrt` < 0, `ln` ≤ 0 → NULL. `factorial`
  outside 0..=20 → NULL. Transcendentals from `core_math`.
- `pow` (`power`, `dpow`, `fpow`): `core_math::pow`, `x*x` when the exponent is constant 2.0.
- `pmod(a, b)` BIGINT: `((a % b) + b) % b`; b = 0 → NULL; `MIN, -1` is mod's coded error.
- `least` (and `greatest`) over INT varargs: any NULL → NULL.
- `bin(BIGINT)`: binary of the two's-complement u64.
- `width_bucket`: the research's integer and double kinds, `n ≤ 0` its INTERNAL_ERROR text.
- `atan2(y, x)` by `core_math::atan2`.
- Cast DATEV2 → DOUBLE/integers is `YYYYMMDD`, DATETIMEV2 is `YYYYMMDDhhmmss`.
