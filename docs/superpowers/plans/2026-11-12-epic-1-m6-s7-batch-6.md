> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** doris-rs runs the math tail, `random`/`sleep`, the statistics and ranking window
functions, the distinct-combinator window aggregates and the encryption/base64 functions as the
C++ BE does. Eligible goes 669 → up to 680, all passing both gates.

**Architecture:**
- **Math** extends `crates/doris-exec/src/math.rs` (unary DOUBLE functions, `log`/`log10`/`log2`,
  `sign`/`signbit`, `negative`/`positive`, `gcd`/`lcm`, `pi`/`e`, `even`, `degrees`/`radians`,
  `fmod`), with the glibc ports in a new `crates/doris-exec/src/glibc.rs`; `round_bankers` goes in
  `round.rs`; `conv` in a new `crates/doris-exec/src/conv.rs`.
- **Random and sleep** go in a new `crates/doris-exec/src/random.rs`: mt19937_64, one generator
  per expression node per fragment instance, drawn in row order.
- **Window aggregates** extend `crates/doris-exec/src/aggregate.rs` (finalizers on the shared
  stddev state, `percentile_approx` as a sorted f32 list, the distinct combinator) and
  `analytic.rs` (`percent_rank`, `cume_dist`, sliding frames for `multi_distinct_count`).
- **Encryption** goes in a new `crates/doris-exec/src/crypto.rs` (`aes_*`, `sm4_*`, `sm3`,
  `sm3sum`, `to_base64`, `from_base64`).

**Tech Stack:** Rust (`doris-exec`, `doris-be`, `doris-fixtures`, `doris-wire`), Python oracle.

**Spec:** `docs/superpowers/specs/2026-11-08-epic-1-m6-query-breadth-design.md` §2 (row 7), §3.

## Calls (the designer's, for the user to check)

- **libm:** core_math for `atan`, `cos`, `sin`, `tan`, `exp`, `log`, `log2`; ports of glibc 2.35
  for `cbrt`, `sinh`, `cosh`, `tanh`, `asinh`, `log10` (the research verified them against the
  reference container's libm). core_math still differs from glibc on about 0.1–0.2% of random
  inputs for exp/sin/cos/tan; no recorded value is affected.
- **`percentile_approx`** is computed exactly while the digest cannot have merged two points,
  and refused, naming it, from 2048 values in one state.
- **`multi_distinct_sum`/`group_concat`** are refused over cumulative frames (C++ re-adds values
  there) and `multi_distinct_group_concat` with two or more distinct strings in one output (C++
  emits them in hash-set order).
- **Unseeded `random()`** draws from an OS-seeded generator; its column is masked by the marks.

## Global Constraints

- Byte-exact replies (spec §3). A feature that cannot match C++ is refused, naming it.
- Never `cargo fmt` whole packages. `rustfmt --edition 2021 --config max_width=150` only on new
  files or files clean at HEAD (check a copy on disk, not stdin); never on test files that
  declare `mod common`.
- `.cache/doris-src` is read-only. FE settings stay unchanged.

## Review Focus

1. **Seeded `random` across instances:** each fragment instance has its own generator; rows take
   consecutive draws in the order the instance emits them.
2. **Empty and one-row frames** for every window function: NULL for a nullable result, `0` for
   the samples, `0`/`1` for percent_rank/cume_dist with one peer group.
3. **Integer overflow** in `gcd`/`lcm`/`negative`: wraps as C++ does, never panics.
4. **NULL and domain errors:** `log*` of `x <= 0` is NULL, `fmod(x, 0)` is NULL, a NULL key or
   IV in the encryption functions.
5. **Wrong-length or corrupt ciphertext** and invalid base64: NULL or the C++ error, never a panic.
