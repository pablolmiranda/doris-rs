# Epic 1 M6 Story 1: CTEs (the multicast sink) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** doris-rs runs fragments whose sink is `MULTI_CAST_DATA_STREAM_SINK`, the FE's plan for a CTE used more than once, and answers as the C++ BE does.

**Architecture:**
- `doris-exec::pipeline` gains `multicast()`. It gives each consumer its own copy of the
  fragment's output chunk, filtered by that consumer's conjuncts and then projected by its output
  exprs.
- Each copy goes through the same stream-send code the `DATA_STREAM_SINK` uses, to that
  consumer's `dest_node_id` and destinations.
- `check_plan` checks every consumer, and `check_senders` counts multicast consumers.

**Tech Stack:** Rust (workspace crates `doris-exec`, `doris-be`, `doris-wire`, `doris-fixtures`), Python oracle (`oracle/`).

**Spec:** `docs/superpowers/specs/2026-11-08-epic-1-m6-query-breadth-design.md` §3, §4.

## Global Constraints

- **Byte-exact replies.** Rows equal the C++ BE's. A feature that can't match the C++ BE's
  reply is refused with a status naming it; a wrong answer is never acceptable.
- **Refuse at prepare.** A plan holding anything doris-rs does not run is refused at prepare,
  naming the first unsupported node, sink, function or expression.
- **No regression.** The ratchets hold. Every eligible suite passes both gates in the story's
  full run (eligible: 349).
- **Checks stay green.** The swap and readback checks pass.
- **Formatting.** Never run `cargo fmt` on whole packages. Format new files only, with
  `rustfmt --edition 2021 --config max_width=150`. Never run rustfmt on test files that declare
  `mod common`.
- **Commits.** Commits end with the session's Co-Authored-By and Claude-Session lines.

## Review Focus

1. A consumer with `output_exprs` but no `output_tuple_id`, or with an empty `conjuncts`
   list. Expected: projected or filtered only when the C++ BE would; an empty list is no filter.
2. A multicast fragment with several instances. Each instance sends to every consumer, so an
   exchange fed by a consumer waits for that many senders.
3. Two consumers feeding the same receiving fragment through two exchange nodes. Each exchange
   gets its own rows; one consumer's filter never leaks into the other's.
4. `sinks` and `destinations` of different lengths. Expected: a BadRequest at prepare, never
   rows sent to the wrong consumer.
5. A consumer partitioned in a way doris-rs does not run. Expected: refused at prepare, naming
   the partition type.

Items 1, 3 and 4 have tests in Task 2. Item 2 is covered by Task 2's sender test. Item 5 is
covered by the existing `check_partition`, which Task 2 applies to each consumer.

### Task 2: The multicast sink

**Files:**
- Modify: `crates/doris-exec/src/pipeline.rs` (`multicast`, the shared stream send, a free `typed`)
- Modify: `crates/doris-exec/src/query.rs` (`check_plan`, `check_senders`)
- Test: `crates/doris-exec/tests/multicast.rs` (new), `crates/doris-be/tests/query.rs`, `crates/doris-be/tests/replay.rs`

**Interfaces:**
- Consumes: Task 1's replay.
- Produces:
  - `pub fn multicast(out: &Chunk, sink: &TMultiCastDataStreamSink, desc: &DescTable) -> Result<Vec<(TDataStreamSink, Vec<TPlanFragmentDestination>, Chunk)>, ExecError>`:
    - one entry per consumer, in `sinks` order;
    - BadRequest when `sinks` and `destinations` differ in length;
    - conjuncts are applied first (an empty or missing list means no filter);
    - then, if both `output_exprs` and `output_tuple_id` are set, the copy is projected onto
      that tuple's slots and typed.
  - `pub fn typed(desc: &DescTable, block: Block, slots: &[i32]) -> Result<Block, ExecError>`:
    the body of today's `Runner::typed`, which now calls it.
  - The runner's `DATA_STREAM_SINK` path and each multicast consumer share one function that
    partitions a chunk and sends it to `(sink.dest_node_id, destinations)`.

- [ ] **Step 1: Write the failing tests.**

  In `crates/doris-exec/tests/multicast.rs`, build a `DescTable` by hand: tuple 0 with slots 1
  (INT `k`) and 2 (VARCHAR `v`), tuple 5 with slot 50 (VARCHAR). The chunk is
  `(1,"a"), (2,"b"), (3,"c")` on slots `[1, 2]`.

  - `each_consumer_gets_its_own_copy`:
    - consumer 0 has conjunct `k > 1` and no projection; it gets rows `(2,"b"), (3,"c")` on
      slots `[1, 2]`;
    - consumer 1 has no conjunct, output_exprs `[slot 2]` and output_tuple_id 5; it gets `"a"`,
      `"b"`, `"c"` on slots `[50]`;
    - the input chunk is unchanged after the call.
  - `filter_comes_before_projection`: the consumer has conjunct `k = 3` and output_exprs
    `[slot 2]` onto tuple 5. It gets one row, `"c"`.
  - `sinks_and_destinations_must_pair`: two sinks with one destination list. The error is a
    BadRequest whose message contains `"multicast"`.

  In `crates/doris-be/tests/query.rs`:
  - `multicast_sender_counts_must_match_the_plan`, modelled on
    `exchange_sender_counts_must_match_the_plan`. It takes the CTE replay's first plan that has
    a multicast sink. The plan as sent is accepted. Clearing the `per_exch_num_senders` of a
    fragment fed by a consumer is refused, with "sender" in the message.

  In `crates/doris-be/tests/replay.rs`:

- [ ] **Step 2: Run them.** `cargo test -p doris-exec --test multicast` and
  `cargo test -p doris-be --test query --test replay`. Expected: they fail to compile
  (`multicast` missing), then fail on `MULTI_CAST_DATA_STREAM_SINK` being refused.
- [ ] **Step 3: Implement.**
  - `multicast` and `typed` as in Interfaces.
  - The runner's sink sends each multicast copy through the shared send. The `sender_id` is the
    instance's, as for a `DATA_STREAM_SINK`.
  - `check_plan`: for `MULTI_CAST_DATA_STREAM_SINK` there must be at least one sink, and the
    sink and destination lists must have equal lengths. Each sink is checked as a
    `DATA_STREAM_SINK` is: its partition, partition exprs, output exprs and conjuncts.
  - `check_senders`: when counting the senders of exchange node `n` in instance `r`, a
    multicast fragment contributes its instance count for each consumer `i` with
    `sinks[i].dest_node_id == n` and `r` in `destinations[i]`.

  (all pass) and `cargo clippy --all-targets --workspace` (no warnings).
