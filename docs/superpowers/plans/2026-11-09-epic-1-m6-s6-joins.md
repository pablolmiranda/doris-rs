# Epic 1 M6 Story 6: Joins — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** doris-rs runs HASH_JOIN_NODE and CROSS_JOIN_NODE, ASSERT_NUM_ROWS_NODE, CASE and
`nullable`, as the C++ BE does: with the same rows, in the same order wherever C++'s order is
fixed. This includes the plans the FE distributes them in (broadcast, shuffle, bucket shuffle,
colocate, local shuffle). Eligible goes 483 → 551, all passing both gates.

**Architecture:**
- **Joins are row functions.** The new modules `hash_join.rs` and `nested_loop.rs` take the
  probe and build rows (plus key values) and return rows in the join's intermediate layout, in
  C++'s order. `pipeline.rs` evaluates the keys, calls them, and evaluates the other and mark
  conjuncts through a callback. It then applies the node's conjuncts, projections and limit, as
  it does for every node.
- **Distribution is planned per fragment.** `query.rs` decides at prepare how each fragment runs:
  - **Merged.** With `parallel_instances` set, the first instance runs with every instance's
    scan ranges. The other instances only end their streams.
  - **Shared broadcast build.** The first instance forwards a copy of the broadcast build input
    to the other instances.
  - **One instance at a time**, for every other fragment, as today.

  `pipeline.rs` gains a bucket-shuffle sink that routes rows with `route.rs`'s crc32.
- **Runtime filters are ignored.** They are neither built, applied, sent nor awaited. Each one
  only drops rows that its join drops anyway.

**Tech Stack:** Rust (`doris-exec`, `doris-be`, `doris-fixtures`, `doris-wire`). No new crates.
Python oracle.

**Spec:** `docs/superpowers/specs/2026-11-08-epic-1-m6-query-breadth-design.md` §2 (row 6),
§3 (the readback join), §5, §6.

**C++ semantics** (Doris 4.1.5, `.cache/doris-src/be/src/`). The full reports, with every
citation, are in `docs/superpowers/research/2026-11-09-m6-s6-{hash-join,nlj-assert-case,join-distribution}.md`. HT = `exec/common/hash_table/join_hash_table.h`,
PI = `exec/operator/join/process_hash_table_probe_impl.h`, BS = `exec/operator/hashjoin_build_sink.cpp`,
NLJP = `exec/operator/nested_loop_join_probe_operator.cpp`.

- **Intermediate layout:** `[left child slots][right child slots][mark]`, taken from
  `vintermediate_tuple_id_list` (`join_probe_operator.cpp:54-62`).
  - LEFT_SEMI, LEFT_ANTI and NULL_AWARE_LEFT_ANTI with no other conjuncts carry left slots
    only (plus the mark). RIGHT_SEMI and RIGHT_ANTI carry right slots only.
  - Slots outside `hash_output_slot_ids` are not materialised. Nothing reads them, so doris-rs
    fills them with NULL.
  - The mark is the last slot, `Nullable(Boolean)`.
  - LEFT/FULL OUTER make the build slots nullable; RIGHT/FULL OUTER make the probe slots
    nullable.
- **Hash join order** (HT:89-101, PI; BS:834-865):
  - Build rows take indexes 1..n in arrival order. Each one is inserted at the head of its
    bucket's chain.
  - Output follows probe-row order. A probe row's matches come out in **descending build
    index**, i.e. reverse arrival order.
  - A LEFT/FULL OUTER probe row with no match is NULL-extended in its own place.
  - After the probe side ends: RIGHT/FULL OUTER emit the unvisited build rows, RIGHT_SEMI the
    visited ones and RIGHT_ANTI the unvisited ones, all in build arrival order (`iterate_map`
    from 1). RIGHT_SEMI and RIGHT_ANTI emit nothing while probing.
  - `batch_size` never reorders.
- **Key equality is bitwise** (`hash_key_type.h:104-152`):
  - DOUBLE −0.0 ≠ 0.0, and NaN matches only the same bits;
  - strings compare by bytes;
  - decimals by raw value;
  - the two key types are equal up to nullability (BS:734-746).

  NULL handling:
  - EQ never matches NULL, and a NULL in any EQ key means the row has no match.
  - EQ_FOR_NULL makes NULL match NULL (BS:753-773).
  - LEFT_ANTI keeps probe rows with a NULL key.
- **Other conjuncts** are two-valued: NULL counts as false (PI:905-911).
  - INNER keeps the passing pairs.
  - LEFT/FULL OUTER: a probe row none of whose pairs pass gets one NULL-extended row.
  - RIGHT/FULL OUTER: a build row is visited only by a passing pair (PI:919-988).
  - LEFT_SEMI emits a probe row once, at its first passing pair; LEFT_ANTI emits it when no
    pair passes (PI:948-978).
- **NULL_AWARE_LEFT_ANTI (not mark):** any NULL build key empties the result, even with other
  conjuncts (BS:323-331). Otherwise NULL probe keys are dropped, except when the build side is
  empty: then every probe row is output (HT:109-114, 245-265).
- **Hash mark joins** (PI:741-892): every probe row is emitted once, with its mark.
  - The mark is TRUE if some candidate passes (the eq match, and the mark and other
    conjuncts).
  - Otherwise it is NULL if any of these holds:
    - the join is null-aware and the probe key is NULL;
    - the join is null-aware and the build side has a NULL key;
    - some candidate evaluated to NULL.
  - Otherwise it is FALSE.
  - ANTI flips TRUE and FALSE; NULL stays NULL.
  - An empty build side gives FALSE (TRUE for ANTI), even for a NULL probe key.
- **ASOF** (`join_utils.h:255-320`): eq keys as usual. Per probe row, `match_condition` is
  `probe OP build` and picks at most one build row:

  | OP | Build row picked |
  |---|---|
  | GE | the largest build ≤ probe |
  | GT | the largest build < probe |
  | LE | the smallest build ≥ probe |
  | LT | the smallest build > probe |

  - A NULL key or NULL ASOF value gives no match; OUTER NULL-extends it.
  - Ties on the ASOF value are broken by an unstable pdqsort, so the row C++ picks among them
    is not one doris-rs can name.
- **Empty build side** (BS:318-339):
  - INNER, LEFT_SEMI, RIGHT_OUTER, RIGHT_SEMI, RIGHT_ANTI and ASOF_LEFT_INNER (not mark) never
    pull the probe child, so errors on the probe side stay hidden. doris-rs's tree pulls
    children first, so it can only match this by evaluating the build child first.
  - Pull the build child (child 1) first. If it is empty for those ops, return without running
    the probe child.
- **Nested-loop join** (NLJP:110-144, 249-377):
  - Pairs come out **probe-major**: P1×B1..Bn, then P2×…, with build blocks in arrival order.
    The join conjuncts filter pairs and keep their order.
  - LEFT/FULL OUTER: unmatched probe rows are appended at the end of each processing call.
    With one probe block whose cross product is under `batch_size`, that means all matched
    pairs first, then the unmatched probe rows in probe order. doris-rs has one probe chunk
    and reproduces that case.
  - RIGHT/FULL OUTER: unmatched build rows come last, in arrival order.
  - SEMI, ANTI and mark: probe rows in probe order.
  - Only `join_conjuncts` is read (`mark_join_conjuncts` is ignored), two-valued, except that
    NULL counts as a match for NULL_AWARE_LEFT_ANTI.
  - The NLJ mark is never NULL: `matched` for SEMI, `!matched` for ANTI and NAAJ.
  - Empty build: INNER, CROSS and SEMI give nothing; OUTER pads with NULLs; ANTI and NAAJ give
    every probe row.
- **ASSERT_NUM_ROWS** (`assert_num_rows_operator.cpp:44-117`). n is the running row count and
  d the desired count:

  | Assertion | Passes when |
  |---|---|
  | EQ | n == d |
  | NE | n != d |
  | LT | n < d |
  | LE | n <= d |
  | GT | n > d |
  | GE | n >= d |

  (Over the whole input; doris-rs sees one chunk.)
  - With `should_convert_output_to_nullable`, EQ 1 over 0 rows gives one all-NULL row and
    passes; otherwise the output types become nullable.
  - Failure is CANCELLED, with the message
    `AssertOperator(node id: {id}) Expected {EQ|NE|LT|LE|GT|GE} {d} to be returned by expression {subquery_string}(actual rows: {n}) `.
    Note there is no space before `(actual` and there is a trailing space.
  - With one chunk, n is the chunk's row count. C++'s n is the count at the failing block,
    which is the same when the child sends one block.
- **CASE** (`exprs/vcase_expr.{h,cpp}`). Children are `[when, then]…[else]`; the FE always sends
  the searched form, and `has_case_expr` is ignored.
  - The first WHEN that is TRUE wins; NULL is not a match. With no match and no ELSE, the
    result is NULL.
  - Quirk: for a non-nullable FLOAT or DOUBLE result, a row's value is
    `Σ (selected_i) × then_i`. So a NaN or ±Inf in an unselected branch makes it NaN, and a
    selected −0.0 becomes +0.0 (`vcase_expr.h:215-266`).
  - Every THEN is evaluated unless its WHEN is false or NULL on every row.
- **`nullable(x)`** passes values through unchanged; it only marks the type nullable
  (`function_nullables.cpp:36-66`).
- **Distribution** (FE `DistributePlanner.java:237-287`, BE `exchange_sink_operator.cpp:142`,
  `partitioner.cpp:31-66`):
  - **Bucket shuffle:**
    - The destination is `crc32 % destinations.len()`, using the same zlib crc32 chain as
      `route.rs`, over each partition expression's value in its own type. Destination `i` is
      the instance that scans bucket `i`.
    - An instance appears once per bucket it owns. An unscanned bucket's destination is
      `(-1,-1)`, and C++ drops its rows.
  - **Colocate and bucket-shuffle scans:** each instance holds whole buckets of every table in
    its fragment, so joining locally is correct.
  - **Shuffle joins:** the FE casts both keys to one type.
  - **OLAP_TABLE_SINK_HASH_PARTITIONED:** the receiving table sink routes each row itself, so
    any split is correct.
  - **Local shuffle** (`parallel_instances` set; FE `UnassignedScanBucketOlapTableJob.java:163-231`):
    - Remote exchanges send only to the first instance.
    - The first instance scans the serial scans for all buckets. The other instances hold
      partial or no scans and no exchange input.
    - Every instance still ends its own stream sink.
  - **Shared broadcast build** (`enable_share_hash_table_for_broadcast_join`, default true):
    - The build exchange of a broadcast HASH_JOIN (not a cross join) is sent only to the first
      instance.
    - The other instances reuse the first instance's table (BS:58-76, 882-907).
  - **Runtime filters:** the merge address is a BE, and every filter RPC goes BE to BE. The FE
    expects nothing. Ignoring all filters leaves results unchanged.

## Calls (the designer's, for the user to check)

- **`assert_true` moves to story 7.** No newly eligible suite uses it, so nothing would check
  it against the C++ BE. Its semantics are recorded above.
- **ASOF joins are built, and ties are refused at run time.** Only `test_asof_join_large_bucket`
  needs them, and it extracts as a replay. When a probe row's best build value is shared by
  several build rows whose output columns differ, the query fails with a status naming "an ASOF
  match among equal values". C++ picks one of them by an unstable sort, which doris-rs cannot
  reproduce.
- **Merged instances, not a local shuffle.** Under `parallel_instances`, C++ spreads the first
  instance's rows over the other tasks, so its row order across instances is not fixed. doris-rs
  runs the first instance over every scan range and has the others end their streams. The rows
  are the same.
- **Runtime filters are ignored.** They save work, and doris-rs's chunks are whole.
- **The NLJ LEFT/FULL OUTER order is C++'s single-call order:** all matched pairs, then the
  unmatched probe rows. C++ interleaves them by call once the cross product passes `batch_size`
  (8160) or the probe side spans several blocks. In those cases C++'s order depends on block
  boundaries that doris-rs does not have; the gate grades those replies unordered unless the
  reference was stable.

## Global Constraints

- **Byte-exact replies.** Rows equal the C++ BE's. A feature that can't match the C++ BE's
  reply is refused with a status naming it; a wrong answer is never acceptable.
- **Refuse at prepare.** A plan holding anything doris-rs does not run is refused at prepare,
  naming the first unsupported node, sink, function or expression. That includes a join op,
  key type pair or sink partition not listed above.
- **No regression.** The ratchets hold, and every eligible suite (551, less any the full run
  proves need a supplement entry, each with its evidence) passes both gates in the full run.
- **The swap and readback checks stay green.** doris-rs answers the readback join in rounds b
  and c.
- **Formatting.** Format new files only, with `rustfmt --edition 2021 --config max_width=150`.
  Never format a test file that declares `mod common`.

## Review Focus

1. **Duplicate keys on both sides.** Three build rows and two probe rows with the same key give
   six rows, each probe row's matches in reverse build order. A RIGHT OUTER tail follows build
   order. These are `hash_join.rs` unit tests in Task 2.
2. **NULLs in keys:**
   - EQ drops NULL keys, but LEFT_ANTI keeps them;
   - EQ_FOR_NULL matches NULL to NULL;
   - multi-key rows with one NULL EQ key never match;
   - NAAJ with a NULL build key is empty, and with an empty build keeps NULL probe keys.

   These are Task 2 and Task 3 unit tests.
3. **Float keys:** −0.0 vs 0.0 and NaN are bitwise, both in the join and when a shuffle sends
   them. A Task 2 unit test covers the join. Task 5 checks that `hash_values` is not used to
   decide equality.
4. **Distribution:**
   - a bucket-shuffle list with a repeated instance and a `(-1,-1)` slot;
   - a merged fragment whose other instances hold scan ranges;
   - a shared broadcast build feeding four instances.

   Each one ends every downstream exchange exactly once and loses no rows: Task 5 tests over a
   constructed `QueryPlan`.
5. **Errors:**
   - an ASSERT_NUM_ROWS failure carries C++'s exact text and CANCELLED;
   - an ASOF tie is refused;
   - an empty build side does not run the probe child for INNER.

   These are Task 4 and Task 6 tests.

  ```rust
  pub fn shared_build(plan: &QueryPlan, fragment: usize, exchange_node: i32) -> bool;
      // the exchange is child 1 of a HASH_JOIN with is_broadcast_join, and the query option
      // enable_share_hash_table_for_broadcast_join is not false
  pub fn bucket_hash(values: &[(ColType, Datum)]) -> u32;   // route.rs, the zlib crc32 chain
  ```
- Behaviour:
  - **Merged:** instance 0 runs the tree with every instance's scan ranges, in instance order.
    Instances 1..N run nothing and end their sink's exchanges with no rows. `check_senders`
    checks exchanges only for instance 0 of a merged fragment.
  - **Shared build:** instance 0 receives the build exchange as usual, then sends a copy and
    an end to the same exchange node of every other instance of its fragment. Those instances
    receive with one sender. `check_senders` expects 0 plan senders for them.
  - **BUCKET_SHFFULE_HASH_PARTITIONED:** the row goes to `destinations[bucket_hash(partition
    values) % destinations.len()]`. Rows for a `(-1,-1)` destination are dropped. Each distinct
    instance gets its rows in one send and exactly one end.
  - **OLAP_TABLE_SINK_HASH_PARTITIONED** splits like RANDOM.
