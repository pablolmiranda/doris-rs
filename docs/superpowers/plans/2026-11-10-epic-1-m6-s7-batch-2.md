# Epic 1 M6 Story 7, Batch 2: Geo, Table Functions, Moments, Dates, Bits — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** doris-rs runs 48 more query features as the C++ BE does, in five families, plus two
pieces of machinery they need. Eligible goes 579 → 621, all passing both gates.

**Architecture:**
- **Scalars** (geo, dates, bits) go in `eval.rs`'s dispatch. Geo gets its own module, `geo.rs`;
  the date arithmetic gets `datetime.rs` (a port of `calc_daynr`, the week calculations and the
  add/sub ranges); bits stay in `eval.rs` and `arith.rs`.
- **Moment aggregates** are new `State` variants in `aggregate.rs`, as `stddev` was in batch 1.
- **Arrays** become a `Datum::Array(Vec<Datum>)` that rows carry, sort keys refuse, and the
  result printer renders. `ColType` gains an element type.
- **TABLE_FUNCTION_NODE** is a new node in `pipeline.rs`, with `explode` and
  `explode_numbers` in a new `table_function.rs`.
- **Two pieces of machinery:** constant subtrees are evaluated at prepare, so their errors come
  back in the `exec_plan_fragment` reply; a scalar first-phase aggregation over several tablets
  keeps one partial state per tablet.

**Tech Stack:** Rust (`doris-exec`, `doris-be`, `doris-fixtures`, `doris-wire`), Python oracle.

**Spec:** `docs/superpowers/specs/2026-11-08-epic-1-m6-query-breadth-design.md` §2 (row 7:
"features are taken in batches, most suites unlocked first, until the user stops it. Its plan
names each batch"), §3.

## Calls (the designer's, for the user to check)

- **The group-commit sink waits for its own batch.** It is the only remaining 4-suite feature,
  none of its suites extract as replays, and research sizes it at several times any family here.
- **v1 DATE/DATETIME are not story 7.** They unlock 146 suites, more than every query feature
  together, but reading v1 columns is storage work the M6 plans keep refused. Raised to the user.
- **Arrays are real values (`Datum::Array`), not pre-rendered text.** `test_split_by_string`
  carries `ARRAY<VARCHAR>` through a sort and an exchange to the result. Text would break the
  first time anything compares one; every match site that cannot handle an array refuses it,
  naming "an ARRAY value".
- **One partial state per tablet, for scalar first-phase aggregations only.** The `regr_*`
  replays come out only when each tablet has its own state, merged in tablet order (C++ splits
  an instance's tablets across pipeline tasks). A grouped aggregation would also change its
  output row order, which the gate already matches; it keeps one state per instance.
- **Random-bucket routing is left as is.** C++ moves to the next tablet per block; doris-rs
  puts an INSERT's rows on one tablet. Query results are the same. If the full run shows a
  difference (`test_ignore`, `sort_spill`), it gets a test and a fix.

## Global Constraints

- Byte-exact replies (spec §3). A feature that cannot match C++ is refused, naming it.
- Never `cargo fmt` whole packages. Format only new files, or files that were clean before the
  change, with `rustfmt --edition 2021 --config max_width=150`. Never rustfmt test files that
  declare `mod common`.
- `.cache/doris-src` is read-only.
- Commits end with the session's Co-Authored-By and Claude-Session lines.

## Review Focus

1. `st_astext` at 15 significant digits: `-0`, `1e-07`, values that round-trip to …9998
   (`POINT (1 1)`), and the exponent boundary at 1e15.
2. `months_add` on the 31st into a 30-day month and 29 Feb into a non-leap year; year 0 is not
   a leap year; going past 9999-12-31 is an error, never NULL.
3. A table function over a NULL or empty input produces no rows (not one NULL row), and with
   two functions the last varies fastest.
4. `kurt`/`skew` over one row or a constant column give NULL; `covar_samp` of one row gives 0.
5. `bit_shift_left` by 64 or a negative count gives 0; `bit_test` with a position past the
   width gives 0.

### Task 2: Bits

- `bitand`, `bitor`, `bitxor` (ARITHMETIC_EXPR) and `bitnot` on TINYINT…LARGEINT, at the
  operand type.
- `bit_count(T)` → TINYINT: the count of set bits of the two's-complement value.

### Task 3: Dates, and constant errors at prepare

**Files:** create `crates/doris-exec/src/datetime.rs`; modify `eval.rs`, `query.rs`
(prepare-time constant pass), `crates/doris-be/src/query.rs` (the `exec_plan_fragment` reply);
tests in `tests/datetime.rs` and `crates/doris-be/tests/`.

Rules (dates-bits research):
- `year` → SMALLINT, `month`/`dayofmonth` → TINYINT, over DATEV2 and DATETIMEV2.
- `{unit}_add/_sub(d, n)` keep the argument type. Year: 29 Feb becomes 28 Feb in a non-leap
  year. Month: the day is clamped to the month's end. Past 9999-12-31 or below 0000-01-01 is an
  error, `Coded{-218, "E-218"}`, text `Operation {unit}_add of {date}, {delta} out of range`
  (`_sub` prints `{unit}_add` with `-delta`; the date has a fraction only when its microseconds
  are non-zero). NULL rows never throw.
- `days_diff/weeks_diff(a, b)` → BIGINT, a−b in days, moved one toward zero when the time-of-day
  difference has the opposite sign; weeks is that / 7. Ported `calc_daynr` (year 0 included).
- `weekofyear(d)` = `week(mode 3)`; `yearweek(d, m)` = `year_week(mysql_week_mode(m))`; year 0
  gives 0.
- `str_to_date(s, fmt)`: the result type is the FE's; `%Y %m %d %H %i %s` are parsed, anything
  else in the format is refused; invalid input gives NULL.
- **Constant pass:** at prepare, every function-call subtree whose leaves are all literals is
  evaluated once; an error fails `exec_plan_fragment` with its code and text, prefixed
  `(127.0.0.1)[E-218]` as the corpus shows.

- [ ] **Step 1: Write the failing tests:** `months_add_clamps_to_month_end`,
  `years_add_leap_day_becomes_28th`, `year_zero_is_not_leap`,
  `add_past_9999_is_e218_with_text` (`years_add('9999-12-31', 1)` →
  `Operation year_add of 9999-12-31, 1 out of range`), `sub_prints_negative_delta`,
  `days_diff_moves_toward_zero` (`'2024-01-02 00:00:00'` − `'2024-01-01 12:00:00'` = 0),
  `weekofyear_mode_3`, `yearweek_mode_6`, `str_to_date_invalid_is_null`, and in doris-be
  `a_constant_overflow_fails_exec_plan_fragment`.
- [ ] **Step 2: Run** `cargo test -q -p doris-exec -p doris-be`. Expected: FAIL.

### Task 5: Moment aggregates

**Files:** `aggregate.rs`, `pipeline.rs` (per-tablet partial states), `eval.rs`
(`non_nullable`); tests in `tests/aggregate.rs`, `tests/run_plan.rs`.

Rules (moments research, which gives every formula in C++ order):
- All take `(DOUBLE[, DOUBLE])` and return nullable DOUBLE.
- `kurt`/`skew` keep power sums; NULL when the count is 0 or the variance is NaN or ≤ 0. Use
  `powf(var, 1.5)`.
- `regr_slope/intercept(y, x)`: Youngs–Cramer, sx/sy updated before the deviation terms; skip a
  row with either NULL; NULL when the result is NaN.
- `corr`, `corr_welford`, `covar`, `covar_samp`, `avg_weighted`: a row with any NULL is
  skipped; a group with no rows is NULL; otherwise the inner value (corr of a constant column 0,
  covar of one row 0.0, covar_samp of 0 or 1 rows 0.0, avg_weighted with zero weights NaN).
- Merge formulas as in the research; intermediate states get new tags in doris-rs's own
  encoding.
- `non_nullable(x)`: the type without nullability; a NULL fails with INVALID_ARGUMENT
  `There's NULL value in column {name} which is illegal for non_nullable`.
- A scalar (no GROUP BY) first-phase aggregation over an instance with several tablets keeps one
  state per tablet and merges them in tablet order.

### Task 7: TABLE_FUNCTION_NODE

**Files:** create `crates/doris-exec/src/table_function.rs`; modify `pipeline.rs`, `query.rs`;
tests in `tests/table_function.rs`.

Rules (tablefn research §1–§2):
- Output columns: the child's slots (a slot not in `outputSlotIds` is NULL), then one per
  function. Per child row the functions nest, first outermost, last fastest. A child row whose
  (non-outer) function is empty produces nothing. `_outer` variants are refused.
- `explode_numbers(n)` → INT 0..n−1; n ≤ 0 or NULL gives nothing. `explode(arr)` → elements in
  order, NULL elements as NULL; NULL or empty gives nothing. Multi-argument `explode` is refused.
- Node conjuncts run after expansion, then projections, then the limit.
